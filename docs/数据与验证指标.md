# 数据与验证指标

> 版本：v0.2（单机离线）
> 最后更新：2026-10-23
> 相关：[产品方案](./产品方案.md) ｜ [工程与开发计划](./工程与开发计划.md)

M0 的唯一目标是验证「这个 AI GM 好不好玩」。好玩不能靠感觉，要先定义能被证伪的指标。单机形态下没有服务端埋点，所有数据先落在设备本地，再由用户自愿导出。

---

## 1. 验证命题

> 用陌生身份进入一个陌生世界，玩家愿意花 40 分钟以上读完第一卷，并且愿意换一个身份重开。

这句话对应三个可测问题：

1. 玩家能不能撑过序章与前 10 回合（留存）
2. 玩家能不能读完整卷（完成度）
3. 读完之后会不会再来一次（重开）

---

## 2. 北极星指标

**首卷完成率** = 完成第一卷的局数 ÷ 进入序章的局数。

选它的理由：它同时要求叙事质量、节奏控制、状态一致性与结局设计都成立。任何一个环节崩了，这个数就掉。

---

## 3. 开局漏斗与初始目标

按设备本地会话统计，不含账号与配额维度。

| 环节 | 定义 | 初始目标 |
| --- | --- | --- |
| 世界打开 → 抽卡 | 进入抽卡页 | ≥ 85% |
| 抽卡 → 开局 | 选定身份并进入序章 | ≥ 80% |
| 序章完成 | 做出第一个关键选择 | ≥ 80% |
| 第 10 回合留存 | 完成第 10 回合 | ≥ 60% |
| 第 20 回合留存 | 完成第 20 回合 | ≥ 40% |
| 首卷完成 | 到达卷末结算 | ≥ 25% |
| 重开 | 结束后 7 天内开新局 | ≥ 20% |

目标值是假设，先用真实数据校准，不要为了达标去改定义。会话以本地 `runId` 与安装 ID 归并，不跨设备拼接。

---

## 4. 指标定义

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 首卷完成率 | 完成第一卷 ÷ 进入序章 | 北极星 |
| 回合留存曲线 | 第 n 回合仍有活跃局的比例 | 找流失点 |
| 中期流失点 | 留存曲线斜率最大的回合区间 | 定位节奏问题 |
| 选项有效性 | 单个选项被选比例 | 低于 8% 视为无效选项 |
| 关键节点参与率 | 有关键节点的回合中做出选择的比例 | 判断是否被跳过 |
| 自由输入使用率 | 使用自由输入的回合占比 | 判断入口是否被发现 |
| 越权处理满意度 | 越权输入后继续游玩的比率 | 判断拒绝体验 |
| 助手使用率 | 每 5 回合至少提问 1 次的比例 | 判断助手价值 |
| 重开率 | 结束后 7 天内新开局比例 | 判断复用价值 |
| 世界线分叉率 | 用回溯开新线的比例 | 判断回溯价值 |
| 平均单局时长 | 从开局到结束的分钟数 | 判断体量 |
| 平均单回合 token | 该回合输入+输出 token 估算，费用由用户 Key 承担 | 判断体量与成本感知 |
| 首字延迟 | 请求到首个 `narration_delta` | 体验硬指标 |
| 平均单回合耗时 | 回合开始到本地落库 | 体验指标 |
| 模型失败率 | 请求失败/超时/解析失败的回合占比 | 稳定性 |
| 降级率 | `degraded = true` 的回合占比 | 稳定性 |
| 提取失败率 | `pendingRepair` 触发比例 | 引擎健康 |
| 终局分布 | 各 ending 占比 | 判断结局设计是否失衡 |
| 导入成功率 | 成功产出世界的导入 ÷ 导入尝试 | 导入链路健康 |

不设每日回合配额，也不做基于账号的用量统计；token 费用只作为用户侧体感指标记录。

## 5. 埋点事件

事件写入本地 SQLite 的 `local_events` 表，默认完全离线、不上报。

| 事件 | 关键属性 |
| --- | --- |
| `world_open` | worldId, source（内置/分享包/本地导入） |
| `draw_start` | worldId, attempt |
| `draw_confirm` | identityId, rarity, difficulty |
| `run_start` | runId, worldVersion, identityId |
| `turn_start` | turnNo, beat |
| `choice_shown` | turnNo, optionCount, risks |
| `choice_made` | turnNo, choiceId, risk, msSinceShown |
| `free_input` | turnNo, kind（action/query/meta/rejected）, length |
| `check_result` | turnNo, grade, margin（不含具体数值给玩家） |
| `assistant_ask` | turnNo, topic |
| `turn_end` | turnNo, latencyMs, tokens, degraded |
| `model_error` | turnNo, provider, code, retried |
| `run_end` | runId, endingId, turns, days |
| `archive_view` | runId, dwellMs |
| `branch_start` | fromSnapshotId, turnNo |

埋点只记录行为，不记录叙事正文全文（正文已在 `run_events`，避免重复与隐私风险）。事件表默认 7 天滚动，仅在用户主动导出时随诊断包带出。

## 6. 定性研究

数据只能说明「在哪掉」，不能说明「为什么掉」。M0 阶段固定做两件事：

1. **可用性测试**：5–8 人，观察第一次游玩，记录卡点与原话。
2. **退出访谈**：流失用户抽样 10 人，只问三个问题——哪一刻不想继续了、当时在期待什么、如果改一件事改什么。

叙事质量另做 5 分制人工评分，覆盖：连贯性、代入感、选择是否有意义、AI 是否越权。

单机形态下访谈与录屏是主要信息源，优先级高于导出数据。

## 7. 实验设计（M0 后）

| 实验 | 变量 | 观察指标 |
| --- | --- | --- |
| 选择频率 | 5–8 回合 vs 3–5 回合 | 第 20 回合留存 |
| 选项数量 | 3 个 vs 4 个 | 决策时长、选项有效性 |
| 文本篇幅 | 150–300 字 vs 300–500 字 | 单回合阅读时长、流失 |
| 自由输入入口 | 常驻 vs 折叠 | 自由输入使用率 |
| 回溯提示 | 结算时提示 vs 主动入口 | 分叉率、重开率 |

一次只改一个变量。单机版本无法做线上分流，实验以版本为单位发布，需邀请测试者安装后自愿导出数据，样本不足时不做结论。

---

## 8. 统计页与诊断导出

- 每日：留存曲线、模型失败率、降级率、首字延迟、平均单回合 token 与耗时
- 每周：开局漏斗、选项有效性、终局分布、流失区间
- 每卷内容更新后：对比新旧版本的完成率

查看入口为 App 内「统计页」；需要更细数据时，设置页「导出诊断数据」生成本地 zip/json 诊断包，由用户主动通过系统分享发出。

统计与导出均按 `world_version` 拆分，否则改内容前后的数据会混在一起，无法判断改动是否有效。

---

## 9. 判定标准

样本 ≥ 200 局、连续观察 2 周后：

- **成立**：首卷完成率 ≥ 25%、第 10 回合留存 ≥ 60%、重开率 ≥ 20%、p95 首字 < 1.5s
- **需调整**：完成率达标但重开率低 → 结局与身份差异不够
- **需重做**：第 10 回合留存 < 40% → 引擎或节奏有结构性问题，先停下做 M1

样本来自早期测试者的自愿导出，存在自选偏差：愿意导出的人更可能玩得深，且设备性能、网络与自带 Key 的模型质量各不相同。结论看方向，不追求小数点精度；做版本对比时只比较同一批测试者。

**不要在核心体验未验证时投入世界创作与分享**，那会把问题放大而不是解决。

## 10. M1–M3 供给与分享指标

M0 验证「玩」，之后验证「造」与「传」。这两层的指标不能沿用玩侧漏斗，否则会把创作者和消费者的数据混在一起。以下数据均来自本地事件表与用户自愿导出。

### 10.1 创作漏斗（M1）

| 环节 | 定义 | 初始目标 |
| --- | --- | --- |
| 进入工坊 → 新建草稿 | 创建 `WorldDraft` | ≥ 60% |
| 新建 → 字段齐备 | 八字段全部达标线 | ≥ 40% |
| 字段齐备 → 生成成功 | `bible_draft` 通过一致性校验 | ≥ 80% |
| 生成成功 → 试玩 | 至少完成 5 回合试玩 | ≥ 50% |
| 试玩 → 保存为可分享世界 | 生成 `.world` 包 | ≥ 30% |

关键定义：**草稿完成率** = 产出可分享包 ÷ 新建草稿；**创作时长中位数** = 新建到导出；**返工率** = 生成后回到访谈重答的草稿占比（> 50% 说明访谈提问质量有问题）。

### 10.2 导入链路（M2）

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 解析成功率 | 成功产出实体 ÷ 导入文件 | ≥ 95% |
| 导入时长 p95 | 选择文件到 `review`（本地 Isolate） | < 8 分钟（20MB 上限） |
| 实体采纳率 | 玩家保留的实体 ÷ 抽取实体 | ≥ 70% |
| 导入世界留存 | 导入草稿在 7 天内被实际游玩 | ≥ 40% |
| 导入世界被导出 | 导入世界出现在 `.world` 包中的次数 | 0（`exportable=false`） |

### 10.3 分享与消费（M3）

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 导出成功率 | 成功生成 `.world` 包 ÷ 导出尝试 | ≥ 98% |
| 导入成功率 | 校验通过并导入成功 ÷ 导入尝试 | ≥ 95% |
| 被开局数 | 单个分享世界在本机的 `run_start` 数 | 中位数 ≥ 5 |
| 导入世界完读率 | 导入世界首卷完成率 | 不低于内置世界的 80% |
| 二次分享率 | 导入后被再次导出的世界 ÷ 被导入世界 | ≥ 10% |
| 存档包迁移成功率 | `.run` 导入成功 ÷ 迁移尝试 | ≥ 90% |
| 创作者留存 | 30 天内产出第二个世界的作者占比 | ≥ 25% |

### 10.4 补充埋点

| 事件 | 关键属性 |
| --- | --- |
| `draft_create` | source（manual/dialogue/import） |
| `draft_field_filled` | field, turnNo |
| `draft_generate` | ok, issueCount, ms |
| `draft_validate_fix` | issueCode |
| `import_start` | bytes, ext, source |
| `import_stage` | stage, done, total |
| `import_review` | keptEntities, totalEntities |
| `export_world` | worldId, ok, bytes, checksumOk |
| `export_run` | runId, worldVersion, ok, bytes |
| `import_run` | ok, worldPresent, reason |
| `import_world` | worldId, ok, reason |
| `card_share` | runId, endingId, channel |
| `feedback_submit` | targetType, reason |

供给侧所有指标按 `world_version` 与 `source` 拆分；导入世界与原创世界必须分开看，否则版权风险会被平均掉。无公开分发渠道，故不统计曝光、举报与审核类指标。
