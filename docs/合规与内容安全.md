# 合规与内容安全

> 版本：v0.5（单机离线）
> 最后更新：2026-10-29
> 适用范围：iOS + Android 双端，纯本地运行，不面向公众提供在线生成服务
> 相关：[世界分享与UGC](./世界分享与UGC.md)

本文件是工程与产品层面的合规要求清单。**具体适用、备案口径与免责边界须由法务与属地监管确认**，本文不构成法律意见。

---

## 1. 前提与定性

产品是一个单机 Flutter App。事实边界如下：

1. **不提供自有生成式 AI 服务**：模型由用户自带的 Key 直连其选择的模型服务（OpenAI 兼容 / OpenAI Responses / Anthropic 三种协议之一），App 不中转、不托管、不代运营。
2. **不托管、不分发用户内容**：所有数据在设备本地 SQLite，没有自建服务端、没有账号、没有社区。
3. **世界分享与存档迁移是本地文件交换**：`.world` 与 `.run`（zip + manifest + checksum）经系统分享面板由用户自行导出/导入，App 不提供公开分发渠道。
4. **仍属 AI 生成内容**：产品输出的叙事与人生卡片为 AI 生成，需按商店与属地要求做标识与分级。

上述形态降低了平台侧义务，但不等于零合规。**仍需以应用商店与属地监管的实际要求为准，上线前复核。**

## 3. 内容安全体系（本地三层）

### 3.1 输入层：本地词表与规则

- App 内置词表与正则规则，输入在本地拦截，命中即拒绝，不发起模型请求
- 覆盖自由输入、世界访谈、导入文件名与元数据
- 词表随 App 版本发布更新；无热更新服务，故更新节奏跟随商店发版

### 3.2 生成层：提示词铁律 + 供应商策略

- 系统提示词写入内容边界（见 [M0 内容包](./M0内容包-修真.md) §10），作为不可被用户覆盖的铁律
- 模型供应商自身的内容策略是第二道防线，由用户所选服务商执行
- 高风险题材（自残、现实暴力教程、未成年人性化）在提示词层硬拒，不做「世界内化」处理
- 流式输出在本地做关键词兜底检查，命中即中断并回退到安全文案

### 3.3 反馈层：本地记录 + 商店渠道

- App 内「举报/反馈」入口只写入本地反馈记录，不联网上报
- 用户可通过商店评价、客服邮箱或系统分享面板主动发出反馈包
- 无 UGC 发布环节，故无平台侧下架、人审与留档流程

三层共用同一套标签体系，避免口径不一致。内容安全不依赖服务端，能力上限取决于本地规则与用户所选模型。

> **落地状态（2026-10-29，WF-LAUNCH-02 交付）**：三层已全部实现并带单测。
>
> - **输入层**：引擎 `ContentSafety`（`packages/engine/lib/src/safety/content_safety.dart`）——标签体系三类（selfHarm / violenceTutorial / minorSexual），正则规则只拦「方法/教程类组合」，不拦题材名词（修真世界「毒药」「杀人」不误杀）。触发点：回合自由输入、世界访谈问答、导入 TXT 文件名，命中即抛 `CONTENT_BLOCKED`（本地拦截，不发起模型请求）。
> - **生成层**：提示词铁律第 7/8 条（Prompt契约 §5 全局铁律 10 条 / §9.1 公共铁律段 8 条）+ 流式兜底——Narrator 流与 Companion 答问在本地逐段检查，命中即中断并以世界口吻安全文案收尾，本回合不落库。
> - **反馈层**：本机 `feedback_records` 表（schema v6）+ `Engine.submitFeedback / listFeedback` + 设置页「反馈与举报」入口，只落本机不联网上报。
>
> 验收（`packages/engine/test/content_safety_test.dart`）：高危样本 20/20 命中（100% ≥ 95%），良性样本 30 条 0 误杀（< 5%，含「劝阻下毒」「炸药坊是铺子」等贴边用例）；引擎全量 171/171 通过，黄金回合 38 PASS。

## 4. AI 生成内容标识

| 位置 | 形式 |
| --- | --- |
| 游玩页 | 页脚固定角标「本故事由 AI 生成」 |
| 世界详情 | 显著位置标注生成方式与模型来源（用户所选服务商） |
| `.world` 包 | `manifest.json` 写入 `aiGenerated: true`，同时写入 `NOTICE.txt` 与来源声明 |
| 人生卡片 / 分享图 | 图片角标「AI 生成」，内容只含结局与关键选择，不含世界定义 |

标识不可由用户关闭或删除；`manifest.json` 中的 `aiGenerated` 在导入、导出与二次分享时原样保留。

> **落地状态（2026-10-29，WF-LAUNCH-03 交付，四处齐备）**：①游玩页——正文流下方固定页脚「本故事由 AI 生成」（非交互、无设置开关，青少年模式开/关两态均常驻，真机截图核对）；②世界详情——`PaperBadge('AI 生成')`；③`.world` 包——`manifest.aiGenerated: true` + `NOTICE.txt` 来源声明，导入时不可关闭、二次分享原样保留（引擎单测）；④人生卡片——文本尾注「※ 本故事由 AI 辅助生成 · 远行」。

## 5. 未成年人保护

- 年龄门槛：首次启动确认年龄；未满 18 岁进入青少年模式
- 青少年模式：关闭自定义世界导入（`.world`）、关闭自由文本输入或加强提示，保留预设选项
- 内容分级：本产品含死亡、暴力后果描写，商店分级与适龄提示必须如实标注
- 未成年人数据：全部留在本机，不采集、不上报、不用于训练
- 风险面：无在线社交、无陌生人互动、无公开内容分发，主要风险为用户自行导入的外部世界文件

> **落地状态（2026-10-29，WF-LAUNCH-04 交付）**：年龄门与青少年模式已实现，护栏做在引擎层而非仅 UI。
>
> - **年龄门**：首次启动展示年龄确认页；选「未满 18 周岁」自动开启青少年模式。选择落 `app_settings`（`AppFlags.ageGate`），之后启动不再弹出。
> - **引擎护栏**（即使某处 UI 漏拦也不会放行，全部在访问文件/网络之前抛 `STATE_INVALID`）：① 回合管线拦截自由输入（`FreeTextInput` 在青少年模式下拒绝，仅选项可推进）；② `LibraryService` 的 `.world` 导出/导入与 `.run` 存档导出/导入四入口；③ 小说导入 `ImportService.start`；④ **随行助手问答**（`assistant()` 收自由文本，与自由输入同口径关闭——2026-10-29 补，堵住经随行问答绕过选项限制的路径）。
> - **UI 门禁**（入口隐藏/锁定）：工坊「导入小说 TXT」卡、世界库管理导入按钮、「我的局」导入图标与各行导出按钮、世界详情「导出分享」菜单项、档案页「导出人生卡片」、游玩页自由输入框（替换为 🔒 提示）、**游玩页随行助手图标（隐藏）**。设置页提供青少年模式开关（带确认弹窗）。
> - 验收：`teen_mode_diagnostics_test.dart` 9/9——自由输入护栏（`STATE_INVALID`、不发起模型请求）、五导入导出入口逐一断言、关闭模式后入口解除；真机（BlueStacks）年龄门→青少年模式全门禁走查→关闭恢复→杀进程重启年龄门不再弹出。
> - 待法务确认项 §10 条 3（时长与输入限制口径）实现取值：无自动退出时长（用户/监护人可在设置页关闭），输入限制为完全关闭自由输入、仅保留预设选项。

## 6. 个人信息与隐私

| 原则 | 落地 |
| --- | --- |
| 最小必要 | 不设账号，不采集姓名、手机号、设备标识；仅本地生成随机安装 ID |
| 数据不出设备 | 游玩数据只写本地 SQLite；唯一外发是用户主动发往其自选的模型服务商 |
| 告知同意 | 首次启动展示隐私政策与用户协议，明确 AI 生成、数据流向与 Key 用途 |
| 凭据安全 | 模型 Key 仅存 iOS Keychain / Android Keystore，不写日志、不进导出包 |
| 存储期限 | 本地数据由用户自行保管，无服务端留存；卸载即删除 |
| 删除权 | 设置页提供「清空全部数据」与单局删除 |
| 可携带权 | 设置页提供「导出数据」：世界走 `.world`、单局走 `.run`，均可在系统文件 App 中管理 |
| 存档外带 | `.run` 含本局叙事正文与状态，属用户内容；导出前二次确认，包内不含 Key、导入原文与用量明细 |
| 不用于训练 | 用户内容不进入任何自有训练流程 |
| 本地日志 | 默认 7 天滚动、仅用于排错，可在设置页手动清除 |

工程约束：`run_events` 属于用户内容，诊断日志属于排错数据，两者分表存放、删除策略不同；导出诊断包时必须剔除 Key 与叙事正文全文。

> **落地状态补记（2026-10-29）**：①「本地日志 7 天滚动」已实现——`Engine.open()` 时自动删除 7 天前的 `local_events` 行（`purgeExpiredLocalEvents()` 亦可手动调用，单测覆盖「旧行删除/近行保留/幂等」）；②诊断文件留存面收敛——每次导出自动只保留最近 5 份（文件含反馈明细），另提供 `clearDiagnostics()` 与设置页「清除诊断文件」按钮（真机验证「已清除 1 个」+ 目录核空）。

> **落地状态（2026-10-29）**：诊断包导出已实现（`Engine.exportDiagnostics()`，设置页「导出诊断数据」按钮，经系统分享面板发出）。脱敏清单——**不含**：模型 Key（Keychain/Keystore，从不读取）、`run_events` 叙事正文、快照、圣经、导入原文；**包含**：`kind/version/generatedAt/schemaVersion`、设置项（不含 Key 字段）、功能开关、9 张表的行数计数、近 30 天用量聚合（请求数/失败/p50/p95/token/回合）、反馈记录（≤200 条，兑现 §8「随诊断包发出」）、近 7 天本地事件（≤200 条，仅类型与回合号）。真机 adb pull 导出文件逐字段核对通过（无 Key、无叙事正文、反馈在列）。

## 7. 知识产权

| 场景 | 规则 |
| --- | --- |
| 内置世界 | 版权归产品方所有，随 App 授权使用 |
| 用户原创世界 | 著作权归用户；App 仅在本机展示，不获取分发许可 |
| 导入小说 | 仅限个人本地自用，`exportable=false`，不随 `.world` 导出，原文不入包 |
| 世界包导出 | 保留 `NOTICE.txt` 与来源声明，不提供公开分发渠道 |
| 侵权投诉 | 无平台分发，投诉走商店与客服渠道；核实后停止相关内置内容 |
| 第三方素材 | 字体、封面、音效需商用授权并留证 |

「导入即私有」在本地数据模型与服务层硬编码（`exportable=false`），不依赖服务端校验。

## 8. 应急与处置

| 事件 | 处置 |
| --- | --- |
| 发现违规内置内容 | 下架对应内置世界，随版本更新移除并留档 |
| 高危舆情 | 暂停相关内置内容入口，发布版本说明 |
| 模型异常输出 | 本地熔断该会话，降级到保守模板并提示用户 |
| 设备丢失 / 数据暴露 | 数据仅在本机；引导用户远程擦除或卸载，Key 在安全存储中可撤销 |
| 反馈集中 | 汇总本地反馈与商店评价，进入下一版本修复 |

处置记录写入本地 `feedback_records`，随诊断包由用户决定是否发出。
