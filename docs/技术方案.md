## 1. 架构总览

```
┌────────────────────── 手机（iOS / Android，同一套 Dart 业务层） ──────────────────────┐
│                                                                                      │
│  Flutter UI（Riverpod / go_router / 纸质排版 / 夜读模式）                              │
│        │  Stream<TurnEvent>（进程内事件流，不是 HTTP SSE）                             │
│        ▼                                                                             │
│  TurnEngine（纯 Dart，可单测）                                                         │
│    分类 → 判定 → 导演 → 叙事流 → 提取 → 校验 → 落库 → 推送                             │
│        │                                    │                                        │
│        ▼                                    ▼                                        │
│  SQLite（drift，本地库）                ModelGateway（三协议适配 HTTPS + SSE）           │
│    worlds / world_versions               │                                            │
│    runs / run_snapshots / run_events     │  Key 从 Keychain / Keystore 读取             │
│    usage_log / import_jobs               │                                            │
│        │                                    │                                        │
│        ▼                                    ▼                                        │
│  本地文件目录（.world 包、导入原文、导出档案）     用户自选的模型服务                        │
│                                          DeepSeek / 通义 / OpenAI / 自建网关 …          │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

三条硬约束：

1. **一切状态在本机。** 没有服务端、没有账号。除模型请求外，App 在飞行模式下可完整浏览已有存档与世界。
2. **模型是唯一外部依赖，且必须可降级。** 网络失败、Key 失效、供应商限流都不能破坏存档；失败发生在落库前，重试安全。
3. **单写入者 + 单局串行。** 一个设备一个 SQLite 写入者；同一 run 同时只处理一个回合，由进程内串行队列保证。

代价也要写清楚：**没有服务端就没有「替用户保管 Key、兜底重试、跨设备同步、内容审核」**。这四项能力分别由「用户自填 Key」「本地降级」「导出/导入」「本地词表 + 商店审核」替代。

## 2. 数据分三层

| 层 | 内容 | 存哪 | 特性 |
| --- | --- | --- | --- |
| 定义层 | `WorldBible`（世界圣经）、身份池、事件种子 | `world_versions` 表 / `.world` 包 | 版本化，冻结后不可改 |
| 实例层 | `Run` + `RunState` 快照 | `runs`、`run_snapshots` | 可序列化、可分支 |
| 记录层 | `run_events` | 本地表 | append-only，可回放、生成人生档案 |

关键点与 v0.1 相同：**状态是快照，事件是流水**，两者分离。回溯、续玩、版本迁移才不互相纠缠。

文件系统分工（App 沙盒内）：

| 目录 | 内容 | 备份 |
| --- | --- | --- |
| `databases/wayfarer.sqlite` | 全部结构化数据 | iOS 随 App 备份；Android 需 `allowBackup` 明确配置 |
| `files/worlds/` | 导入的 `.world` 原件、内置世界解包产物 | 否 |
| `files/imports/` | 小说导入的 TXT 原文（私有，不可导出） | 否 |
| `files/exports/` | 用户主动导出的 `.world`、人生档案 | 否 |

**导入原文只进沙盒私有目录，永不出现在导出包与分享路径中。**

## 3. 表结构（M0 需要 9 张 + 1 张 FTS）

```sql
-- 迁移版本由 drift 的 schemaVersion 落到 PRAGMA user_version，不单独建表

CREATE TABLE worlds (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  genre TEXT NOT NULL,
  summary TEXT,
  source TEXT NOT NULL,                         -- builtin | created | imported | shared
  exportable INTEGER NOT NULL DEFAULT 1,        -- 小说导入来源为 0，App 内禁止导出
  latest_version INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

-- 冻结即新版本；老存档永远读自己那版
CREATE TABLE world_versions (
  id TEXT PRIMARY KEY,
  world_id TEXT NOT NULL REFERENCES worlds(id) ON DELETE CASCADE,
  version INTEGER NOT NULL,
  bible TEXT NOT NULL,                          -- WorldBible JSON
  identities TEXT NOT NULL,                     -- Identity[] JSON
  seeds TEXT NOT NULL,                          -- EventSeed[] JSON
  checksum TEXT NOT NULL,                       -- 内容校验和，导入时比对
  created_at INTEGER NOT NULL,
  UNIQUE(world_id, version)
);

CREATE TABLE runs (
  id TEXT PRIMARY KEY,
  world_id TEXT NOT NULL,
  world_version INTEGER NOT NULL,
  identity_id TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'active',        -- active | ended | abandoned
  chapter INTEGER NOT NULL DEFAULT 1,
  turn_no INTEGER NOT NULL DEFAULT 0,
  head_snapshot_id TEXT,
  ending_id TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

-- 回溯重开 = 从快照新建 run，parent_snapshot_id 指向旧快照，旧世界线原样保留
CREATE TABLE run_snapshots (
  id TEXT PRIMARY KEY,
  run_id TEXT NOT NULL REFERENCES runs(id) ON DELETE CASCADE,
  turn_no INTEGER NOT NULL,
  chapter INTEGER NOT NULL,
  parent_snapshot_id TEXT,
  parent_run_id TEXT,
  state TEXT NOT NULL,                          -- RunState JSON
  memory TEXT,                                  -- 卷末压缩产物，仅卷首有值
  created_at INTEGER NOT NULL
);

CREATE TABLE run_events (
  run_id TEXT NOT NULL REFERENCES runs(id) ON DELETE CASCADE,
  seq INTEGER NOT NULL,
  turn_no INTEGER NOT NULL,
  type TEXT NOT NULL,   -- input|narration|choice|check|delta|rejected|compact|system
  payload TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  PRIMARY KEY (run_id, seq)                     -- 天然去重、天然有序
);

-- 本地用量与成本估算，供设置页统计；不联网上报
CREATE TABLE usage_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  run_id TEXT, turn_no INTEGER,
  role TEXT NOT NULL,                           -- classifier|director|narrator|extractor|companion|compress
  model TEXT NOT NULL,
  tokens_in INTEGER NOT NULL,
  tokens_out INTEGER NOT NULL,
  ms INTEGER NOT NULL,
  ok INTEGER NOT NULL DEFAULT 1,
  created_at INTEGER NOT NULL
);

-- M2 小说导入的本地作业，可中断续跑
CREATE TABLE import_jobs (
  id TEXT PRIMARY KEY,
  source_path TEXT NOT NULL,
  content_hash TEXT NOT NULL,
  stage TEXT NOT NULL,                          -- parse|extract|merge|review|done|failed
  progress REAL NOT NULL DEFAULT 0,
  error TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

-- 非敏感设置。Key 绝不入此表
CREATE TABLE app_settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

-- 本地漏斗事件（开局、抽卡、留存等），默认只存本机、不上报
CREATE TABLE local_events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  run_id TEXT,
  props TEXT,                                   -- JSON
  created_at INTEGER NOT NULL
);

CREATE INDEX idx_runs_world ON runs(world_id, status, updated_at);
CREATE INDEX idx_snapshots_run ON run_snapshots(run_id, turn_no);
CREATE INDEX idx_events_run_turn ON run_events(run_id, turn_no);
CREATE INDEX idx_local_events_name ON local_events(name, created_at);

-- M0 检索用 FTS5，不引向量库
CREATE VIRTUAL TABLE events_fts USING fts5(
  run_id UNINDEXED, turn_no UNINDEXED, text, tokenize = 'unicode61'
);
```

`runs.world_version` 一旦绑定就不再跟随世界升级。否则用户改一次世界，所有存档全废。

## 4. 世界圣经 WorldBible

> 完整字段、子结构与校验约束以[数据契约](./数据契约.md) §2 为准；本节只列骨架与设计意图。

```ts
type WorldBible = {
  schemaVersion: 1;
  meta: {
    title: string;
    genre: 'xianxia';
    tone: string;                  // 基调，如「冷峻、克制、少抒情」
    pov: 'second';                 // 叙述人称：第二人称「你」
    language: 'zh-CN';
    contentRating: 'general';
  };
  eras: Era[];                     // 时代与历史大事件
  regions: Region[];               // 地理与场所
  factions: Faction[];             // 势力与派系
  powerSystem: {
    name: string;                  // 如「灵根 / 周天」
    tiers: Tier[];                 // 炼气、筑基、金丹……含寿元上限
    rules: string[];               // 力量体系硬规则
    costs: string[];               // 使用代价，防止无限开挂
  };
  taboos: string[];                // 世界禁忌，AI 不得违背
  npcPool: NpcSeed[];              // 预置 NPC（含私密设定，玩家不可见）
  eventSeeds: EventSeed[];         // 未触发的事件种子
  endgame: EndingRule[];           // 终局条件
};

type Tier = { name: string; lifespan: number; requires: string; breakthroughRisk: number };
type EndingRule = { id: string; type: 'death' | 'ascension' | 'fall' | 'legacy'; condition: string; title: string };
```

设计约束（不变）：

- `taboos` 与 `powerSystem.rules` 以最高优先级注入每回合上下文，是防止 AI 自我崩坏的锚点。
- `npcPool` 分「公开面」与「私密面」：私密面只进导演上下文，永不进叙事，用来支撑信息差。
- `eventSeeds` 不是剧本，是带前置条件的触发点；由引擎判断是否满足，避免 AI 凭空造大事件。

## 6. 运行时状态 RunState

> 完整子结构、默认值与数值范围见[数据契约](./数据契约.md) §4。

```ts
type RunState = {
  schemaVersion: 1;
  meta: {
    chapter: number;
    turnNo: number;
    gameTime: string;               // 世界内时间，只进不退
    age: number;
    lifespan: number;               // 寿元，只减不增；突破时由代码上调
  };
  character: {
    name: string;
    identityId: string;
    realm: { stage: string; layer: number; progress: number };
    stats: { vitality: number; spirit: number; body: number };
    resources: { spiritStones: number; pills: Record<string, number> };
    conditions: { id: string; label: string; severity: number }[];
  };
  location: { regionId: string; placeId: string };
  relations: Record<string, { affinity: number; trust: number; status: string }>;
  inventory: { id: string; name: string; qty: number }[];
  knowledge: string[];              // 只存「主角知道的」
  threads: { id: string; desc: string; dueChapter?: number; status: 'open' | 'closed' }[];
  flags: Record<string, string | number | boolean>;
  reputation: Record<string, number>;
};
```

`knowledge` 是这套设计里最值钱的字段。**世界真相在圣经里，主角只知道 `knowledge` 里的事。** 由此得到三个能力：

1. 助手不会剧透（随行模式只读 `knowledge`）
2. NPC 可以骗你（导演能看到真相，叙事只表达角色视角）
3. 玩家因「知道得比别人多」而产生真实优势

## 7. StateDelta：AI 唯一被允许的输出

```ts
type StateDelta = {
  ops: Op[];
  facts: string[];                 // 本回合新增的既成事实，进 canon，不可推翻
  openThreads?: Thread[];          // 新埋的伏笔
  closeThreads?: string[];         // 回收的伏笔
};

type Op =
  | { op: 'set'; path: string; value: unknown; reason?: string }
  | { op: 'inc'; path: string; by: number; reason?: string }
  | { op: 'push'; path: string; value: unknown; reason?: string }
  | { op: 'remove'; path: string; reason?: string };
```

### 7.1 可写路径白名单

完整路径模式、类型与范围见[数据契约](./数据契约.md) §5.1。

`character.*`、`relations.*`、`location`、`inventory`、`threads`、`flags`、`knowledge`、`reputation`、`meta.gameTime`、`meta.age`

### 7.2 禁止写入

世界圣经、其他 run 的状态、`ending_id`、`lifespan` 的上调（只能由突破流程修改）、`meta.chapter`。

### 7.3 校验顺序与容错

1. 路径命中白名单
2. 值通过类型与范围校验
3. 数值 clamp（气血 `>= 0`，寿元只减不增）
4. 时间单调递增
5. 角色死亡后拒绝一切行动类 op

**逐条容错，不重试整回合。** 非法 op 丢弃并写入 `run_events(rejected)`，剩余合法 op 正常生效。整回合重试既贵又慢，且大概率仍会错。

## 8. 回合流程（进程内）

> 完整方法签名、事件与错误类型见 [API 参考](./API参考.md)。本节只描述回合本身的契约。

```
TurnEngine.runTurn(runId: String, input: TurnInput) → Stream<TurnEvent>
```

`TurnInput` 二选一：`ChoiceInput(choiceId)` / `FreeTextInput(text)`。调用方（PlayController）必须带上 UI 当前看到的 `expectedTurn`。

事件顺序固定：

| 事件 | 载荷 | 说明 |
| --- | --- | --- |
| `turnStart` | `{ turn }` | 回合开始 |
| `classification` | `{ kind }` | 仅自由输入：`action` / `query` / `meta` / `rejected` |
| `narrationDelta` | `{ text }` | 多次，流式正文 |
| `narrationEnd` | `{}` | 正文结束 |
| `choices` | `{ options }` | 3–4 个选项 |
| `statePatch` | `{ delta }` | 客户端据此更新数值面板 |
| `turnEnd` | `{ turn, snapshotId, ending? }` | 落库完成 |
| `turnError` | `{ code, message, canRetry }` | 终态，不会与 `turnEnd` 同时出现 |

并发与幂等（本地版）：

- 同一 `runId` 的 `runTurn` 由**进程内串行队列**串行化；第二个调用挂起等待，不返回 409。
- `expectedTurn` 与 `runs.turn_no` 不一致时抛 `TurnConflictException`，UI 重新读库刷新，不自动重放。
- **幂等靠事务而非幂等键**：一回合的状态写入（snapshot + events + run 头）在单个 SQLite 事务内完成，失败整体回滚；UI 在 `submitting` 期锁按钮。
- App 被系统杀死发生在落库前 = 这一回合不存在，重进后可重试；发生在落库后 = 已提交，不会重复扣费。

**前端铁律：数值面板只读 `statePatch`，绝不从正文解析数字。** 否则同一份幻觉会从前端漏出去。

## 9. 选项 Choice

> 完整定义与 `ScenePlan` 见[数据契约](./数据契约.md) §7。

```ts
type Choice = {
  id: string;
  label: string;                                   // 给玩家看的文案
  intent: string;                                  // 给导演看的意图，与 label 分离
  risk: 'low' | 'medium' | 'high';                 // 只给暗示，不给数值
  requires?: { knowledge?: string[]; items?: string[]; realm?: string };
  hidden?: boolean;                                // 条件不满足则整条不出现
  check?: { stat: 'body' | 'spirit' | 'luck'; dc: number };  // 由代码掷骰
};
```

`label` 与 `intent` 必须分开：文案可以写得很文学，引擎照样知道这一步要达成什么。合在一起会逼 AI 去猜玩家意图。

## 10. 上下文预算（固定 8k）

| 层 | 内容 | tokens |
| --- | --- | --- |
| 固定 | 世界圣经摘要 + 禁忌 + 力量规则 | 1500 |
| 固定 | 身份卡 + 当前目标 | 300 |
| 慢变 | 卷末压缩（事实 / 关系 / 伏笔） | 1200 |
| 检索 | 相关 NPC、地点、往事片段 | 1500 |
| 近期 | 最近 3 回合原文 | 2000 |
| 输入 | 玩家动作 + 输出约束 | 800 |
| 余量 | | 700 |
| **合计** | | **8000** |

预算是「不随局数增长」的硬保证：第 200 回合与第 1 回合的输入规模一致，这是「可以无限玩」的技术前提。在手机上这也意味着单次请求体固定、内存占用可控。

注意：不同供应商的 tokenizer 有差异，8k 是**估算预算**；`ModelGateway` 在发送前按字符数 × 系数换算，并留出 10% 余量。若用户选的模型上下文窗口小于 8k，引擎自动降到 6k 档并在设置页提示。

## 11. 记忆与压缩

### 11.1 四层记忆

| 层 | 内容 | 更新频率 |
| --- | --- | --- |
| 永久 | 世界圣经摘要、身份卡 | 永不 |
| 慢变 | 卷末压缩产物 | 每卷一次 |
| 检索 | 实体相关片段 | 每回合按需 |
| 近期 | 最近 3 回合原文 | 每回合 |

### 11.2 卷末压缩

一卷结束（20–40 回合）触发一次任务，输入本卷全部事件，输出四样：

1. 事实清单（不可推翻的既成事实）
2. 人物关系变化
3. 未回收伏笔
4. 300 字卷记

本地执行方式：**在一次前台会话内用 Isolate 跑**，不阻塞 UI；App 进入后台或被杀死则任务标记为未完成，下次启动时在设置页或卷首提示续跑。产物写入 `run_snapshots.memory`（仅卷首快照有值）。

### 11.3 检索方案

**M0 不上向量库。** 用实体标签 + 本地 FTS5（`events_fts`），按「当前地点、在场 NPC、开放伏笔」召回。等出现明确的召回精度问题再引入向量（需在设备端跑 embedding，成本与包体都要重新评估）。

## 12. 版本与迁移

- `runs.world_version` 绑死，世界升级不迁移旧档。
- `RunState.schemaVersion` 独立字段，引擎升级时按版本跑本地迁移函数（`migrate(state, from, to)`）。
- `world_versions.checksum` 用于 `.world` 导入时校验内容完整性与来源一致。
- drift 的 `schemaVersion` 管理库结构迁移，只增不改；每次升级提供 `MigrationStrategy` 的单测。
- 回溯产生的分支 run 通过 `run_snapshots.parent_snapshot_id` + `parent_run_id` 建立世界线谱系。

## 13. 成本与设备资源

**模型费用由用户自己的 Key 承担。** 每回合 2–3 次调用，输入约 6–8k，输出 1–2k；按国产模型价格估算，单回合约 1–3 分钱，一局两百回合约几元。App 只做估算与统计，不抽成、不设每日回合上限。

设备侧预算：

| 项 | 估算 | 约束 |
| --- | --- | --- |
| 单回合存储 | 事件 + 快照约 4–8 KB 纯文本 | 200 回合约 1–2 MB，可忽略 |
| 单局内存峰值 | 上下文 8k tokens + 流式缓冲 | 控制在 30 MB 内，避免低端机被杀 |
| 单回合耗时 | 3 次模型调用，8–20 s | 必须有流式与可取消 |
| 电量 | 长连接等待为主 | 不做轮询，无后台常驻 |
| 冷启动 | 打开即读本地库 | 首屏不依赖网络 |

模型调用的三条成本控制（与 v0.1 一致，但执行方从服务端变成引擎）：

- 上下文固定预算，不随局数增长
- 世界圣经前缀在同一回合内复用（同一请求内，不跨请求缓存，因为多数供应商的缓存由服务端自行决定）
- 卷末压缩用小模型

## 14. 已定与边界

- 模型网关：三协议适配（OpenAI Chat Completions / OpenAI Responses / Anthropic Messages），同一时刻只用一套配置；不做多供应商自动聚合、不做自动降级换家。
- 记忆检索：M0–M3 用实体标签 + FTS5；不引向量检索，召回层留统一接口，见 §6。
- 存档迁移：世界走 `.world`、存档走独立 `.run` 包；`.run` 只承载单局，绑定 `worldId + worldVersion`。
- 助手：仅随行模式，只读 `knowledge`，禁止剧透。

判定落点已定：**执行行动时结算，且在叙事之前**，见[规则与判定系统](./规则与判定.md) §2。
