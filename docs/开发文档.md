## 1. 环境准备

| 组件 | 版本要求 | 用途 |
| --- | --- | --- |
| Flutter | ≥ 3.24（Dart ≥ 3.5） | App 与全部业务代码 |
| Xcode | 最新稳定版 | iOS 真机 / 模拟器 |
| Android Studio + SDK | 最新稳定版 | Android 真机 / 模拟器 |
| SQLite CLI | 任意 | 直接查看本地库（可选） |

不需要 Node.js、npm、Docker、任何本地服务。**整个项目只有 Flutter 工具链。**

首次准备：

```
flutter pub get
dart run build_runner build --delete-conflicting-outputs
cd apps/mobile && flutter run
```

启动顺序固定为 **契约生成 → 引擎测试 → App**。序列化代码没生成，引擎编译不过；引擎测试不过，App 只会白屏或空列表。

## 2. 模块职责

### 2.1 引擎（`packages/engine`，纯 Dart，禁止 import Flutter）

```

│  ├─ context.dart         上下文装配与 8k 预算裁剪
│  ├─ validate.dart        StateDelta 白名单校验与逐条容错

│  └─ compress.dart        卷末压缩（Isolate）
├─ rules/
│  ├─ resolver.dart        成功率、掷骰、分级
│  ├─ growth.dart          突破、境界、寿元
│  └─ ending.dart          终局触发
├─ prompts/
│  ├─ classifier.dart  director.dart  narrator.dart  extractor.dart  companion.dart
│  └─ fragments/           铁律、文风、schema 说明
├─ llm/
│  ├─ gateway.dart         模型适配层（重试、超时、记账）
│  ├─ openai_compatible.dart 请求构造与流式解析
│  └─ llm_errors.dart      供应商错误 → EngineCode 映射
├─ data/
│  ├─ database.dart        drift 数据库与连接
│  ├─ migrations.dart      只增不改的迁移
│  └─ dao/                 worlds runs snapshots events usage imports settings
└─ world/
   ├─ package.dart         .world 打包 / 解包 / 校验
   └─ seed.dart            内置世界导入
```

规则：

1. `turn_engine.dart` 是唯一写 `run_snapshots` / `run_events` 的地方。
2. `llm/gateway.dart` 是唯一模型出口，业务代码只传 `role` 与消息。
3. prompt 文本放 `prompts/`，不写在业务函数里，便于回归。
4. `rules/` 是纯函数，不读库、不调模型、不读时钟。

## 4. 数据层

### 4.1 迁移

- 迁移写在 `packages/engine/lib/src/data/migrations.dart`，用 drift 的 `schemaVersion` + `MigrationStrategy`。
- 只增不改：新版本只能 `addColumn` / `createTable` / `createIndex`，不删列、不改类型。
- 每次升版本必须补一条单测：从 0 迁移到最新，再插入一条 `RunState` 读回比对。
- 表结构以[技术方案](./技术方案.md) §3 为准。

- 苍梧内容包随 App 打包：`assets/seed/cangwu/bible.json`、`identities.json`、`seeds.json`、`volume1.json`。

## 5. 引擎实现

### 5.1 回合编排

`turn_engine.dart` 是全系统唯一推进回合的函数，骨架如下：

```dart
Stream<TurnEvent> runTurn(String runId, TurnInput input, {required int expectedTurn}) async* {
  // 0. 串行 + 乐观校验
  final run = await _runs.get(runId);
  if (run == null) throw const EngineException(EngineCode.notFound);
  if (run.turnNo != expectedTurn) throw const EngineException(EngineCode.turnConflict);

  yield TurnStart(run.turnNo + 1);

  // 1. 分类（仅自由输入；选项点击跳过）
  final intent = switch (input) {
    ChoiceInput() => IntentKind.action,
    FreeTextInput(:final text) => await _classifier.classify(text),
  };
  if (input is FreeTextInput) yield Classification(intent);
  final text = input is FreeTextInput ? input.text : '';

  // 1.1 查询与 meta 不推进回合：查询走 Companion，meta 走本地 FAQ，均直接收尾
  if (intent == IntentKind.query || intent == IntentKind.meta) {
    final answer = intent == IntentKind.meta
        ? _faq.answer(text)
        : await _companion.answer(run.state, text);
    yield NarrationDelta(answer);
    yield const NarrationEnd();
    yield TurnEnd(turn: run.turnNo, snapshotId: null, ending: null);   // 不写库、不推进
    return;
  }

  // 2. 判定（纯代码，在叙事之前）；越权不做判定，交给导演写成世界内拒绝
  final check = intent == IntentKind.action ? _resolver.resolve(run.state, input) : null;

  // 3. 导演（拿到判定的确定结果后再规划场景）
  final plan = await _director.plan(run.state, check);

  // 4. 叙事（流式；受 plan 约束）
  final buffer = StringBuffer();
  await for (final delta in _narrator.stream(plan)) {
    buffer.write(delta);
    yield NarrationDelta(delta);
  }
  yield const NarrationEnd();

  // 5. 提取（把叙事反解为 StateDelta）；越权分支不提取、不写状态
  if (intent == IntentKind.rejected) {
    final snapshotId = await _db.commitTurn(runId, run.state, EmptyDelta(), buffer.toString(), plan, null, advanceDays: 0);
    yield TurnEnd(turn: run.turnNo + 1, snapshotId: snapshotId, ending: null);  // 只留正文，不发 choices / statePatch
    return;
  }
  final delta = await _extractor.extract(buffer.toString(), plan);

  // 6. 校验（逐条，非法 op 丢弃并记录，不整回合重试）
  final validated = _validate.apply(run.state, delta);

  // 7. 应用、快照、事件、结算检查
  final next = _apply.ops(run.state, validated.accepted);
  final ending = _ending.check(next);

  // 8. 单事务落库后才发 choices 与 statePatch
  final snapshotId = await _db.commitTurn(runId, next, validated, buffer.toString(), plan, ending);
  yield ChoicesAvailable(plan.nextChoices);
  yield StatePatch(validated.accepted);
  yield TurnEnd(turn: next.meta.turnNo, snapshotId: snapshotId, ending: ending);
}
```

顺序铁律：**分类 → 判定 → 导演 → 叙事 → 提取 → 校验 → 落库 → 推送**。判定必须在叙事前，否则模型会先写结果再倒推合理性。

失败处理：

| 环节失败 | 处理 |
| --- | --- |
| 分类超时 | 按 `action` 兜底，记录 `degraded` |
| 导演输出不可解析 | 用上回合 `beat` 重试一次，仍失败则走降级场景 |
| 叙事中断 | 保留已生成正文，发 `narrationEnd` 与重试提示，不写库 |
| 提取失败 | 用规则兜底（时间推进、无状态变化），标记 `pendingRepair` |
| 校验全丢 | 本回合视为无效，抛 `STATE_INVALID`，允许重试 |

### 5.2 串行队列

```dart
class RunQueue {
  final _tail = <String, Future<void>>{};
  Future<T> run<T>(String runId, Future<T> Function() task) {
    final prev = _tail[runId] ?? Future.value();
    final completer = Completer<void>();
    _tail[runId] = completer.future;
    return prev.then((_) => task()).whenComplete(completer.complete);
  }
}
```

要求：

1. 同一 `runId` 的 `runTurn` 全部经过队列，不允许两个流并发写库。
2. 队列只在进程内有效；App 被杀后无残留锁（SQLite 事务保证一致性）。
3. UI 侧仍必须锁输入，队列不是防重复点击的第一道防线。

### 5.3 Validator

白名单在 `validate.dart` 单一维护，与[技术方案](./技术方案.md) §7 的路径表一一对应：

```dart
const allowed = <String, ValueKind>{
  'character.stats.vitality': ValueKind.number,
  'character.stats.spirit': ValueKind.number,
  'character.stats.body': ValueKind.number,
  'meta.gameTime': ValueKind.string,
  'meta.age': ValueKind.number,
  'location.regionId': ValueKind.string,
  'location.placeId': ValueKind.string,
  // …其余按文档补齐
};
```

实现要点：

1. 先查路径是否在白名单，不在直接拒，不做「猜测意图」。
2. 数值 op 必须带 `reason`，缺 `reason` 拒。
3. 单次回合内同路径多次 op，按顺序叠加后统一 clamp，不逐条 clamp。
4. 拒掉的 op 写进 `run_events(type = 'rejected')`，供调参与回归使用。
5. 任何情况下不允许 `delete` 整个对象、不允许写 `meta.chapter` 与 `lifespan` 上调。

### 5.4 Resolver

纯函数，不读库、不调模型、不读系统时钟：

```dart
ResolveResult resolve(RunState state, TurnInput input, {required Random random});
// → grade / roll / margin / successRate / consequences
```

- 输入只来自 `state` 与行动描述，禁止读 `threads` 的隐藏字段（防剧透）。
- 骰子用注入的 `Random`，测试传固定 seed，保证可重放。
- `grade` 五级：`critical_success` / `success` / `narrow` / `fail` / `critical_fail`（见[数据契约](./数据契约.md) §6）。
- 公式与阈值只写在 `resolver.dart` 顶部常量，不在别处出现魔法数字。

### 5.5 模型网关

`llm/gateway.dart` 只暴露三个方法：

```dart
Future<ChatResult> chat({required Role role, required List<Message> messages, bool json = false, int? maxTokens, Duration? timeout});
Stream<String> stream({required Role role, required List<Message> messages, Duration? timeout});
Future<ConnectionReport> testConnection();
```

要求：

1. Key 每次从 `SecureKeyStore` 读，不缓存到全局变量、不写日志。
2. 统一重试：网络错误 2 次、超时 1 次、429 按 `Retry-After` 1 次、4xx 不重试。
3. 每次调用写 `usage_log`（`role / model / tokensIn / tokensOut / ms / ok`）。
4. JSON 模式优先协议原生字段（`openai_chat` 的 `response_format`、`openai_responses` 的 `text.format`）；Anthropic 无原生 JSON 模式，直接走前缀约束 + 本地校验。400 时去掉该字段重试一次，再退化为「前缀约束 + 截断修复」，规则见[Prompt 契约](./Prompt契约.md)。
5. 业务代码不得出现具体模型名，只出现 `role`。

### 5.5.1 协议适配

```
llm/
  gateway.dart          # 唯一出口：角色 → 模型、重试、超时、记账
  adapters/
    openai_chat.dart    # POST {baseUrl}/chat/completions
    openai_responses.dart # POST {baseUrl}/responses
    anthropic.dart      # POST {baseUrl}/v1/messages
```

- 适配器只做三件事：组请求、解流、归一错误码；业务层只看到 `Stream<String>` 与 `ChatResult`。
- 新增协议 = 新增一个适配器 + 一条 mock 测试，不改编排代码。
- 请求/帧格式、预设值见 [API 参考](./API参考.md) §5.1–§5.2。
- Key 注入方式不同：`openai_*` 用 `Authorization: Bearer`，`anthropic_messages` 用 `x-api-key` + `anthropic-version`。

### 5.6 上下文装配

`context.dart` 按[Prompt 契约](./Prompt契约.md) §3 的七段装配：系统 → 世界 → 身份 → 记忆（压缩产物）→ 检索 → 近况 → 任务，顺序固定。裁剪策略：

1. 稳定前缀（系统段 + 圣经摘要）每回合重算但内容不变，供应商侧缓存是否命中由对方决定。
2. 近期正文按回合从新到旧截断，保证最后一回合完整。
3. 伏笔按「即将到期」优先保留。
4. 任何一段超预算时，先压实体摘要，再压事实清单，最后才动近期正文。
5. 发送前按字符数 × 系数估算 token，超 8k 直接裁到 8k，留 10% 余量。

### 5.7 卷末压缩

`compress.dart` 在一次前台会话内 `Isolate.run` 执行，输入本卷事件，输出事实清单 / 关系变化 / 未回收伏笔 / 300 字卷记，写入卷首快照 `memory`。

- 不阻塞 UI；压缩期间可继续阅读，但不能推进下一回合。
- App 被挂起或杀死 → 任务未完成，下次启动在卷首提示「补写卷记」。
- 压缩失败不阻断游戏：使用上一卷的 memory + 本卷事件摘要兜底。

## 6. 客户端实现

### 6.1 PlayController

状态机：`idle → streaming → awaitingChoice → submitting → idle`；异常进 `error`；未配置模型进 `blocked`。

规则：

1. 只有 `awaitingChoice` 接受玩家输入。
2. `submitting` 期间再次点击忽略，不发第二个请求。
3. 收到 `statePatch` 才更新数值，不从正文里抓数字。
4. 收到 `turnEnd` 才解除输入锁；`narrationEnd` 只负责选项淡入。
5. 流中断时保留已渲染正文，按钮变「重试」，重试带上 `expectedTurn`。
6. `blocked` 态点击输入 → 跳设置页，不消耗任何调用。

### 6.2 流式渲染

- 引擎返回的是 `Stream<TurnEvent>`，UI 直接 `await for`；不存在网络 SSE 客户端。
- 正文以 `TextSpan` 增量追加，每 80–120 ms 合并一次 setState，避免每 token 重建。
- 自动跟随：用户上滑即停止跟随并显示「回到最新」。
- 事件乱序不可能发生（同一条流顺序产出）；未知事件类型忽略并记日志。

### 6.3 本地数据即主库

v0.2 没有「服务端权威状态」，因此：

- 读页面直接读 drift，不做二次缓存层。
- 写只经引擎，UI 不直接 `update`。
- 冷启动、从后台返回一律以库为准；内存里的 `RunState` 只是渲染副本。
- 删除、清空必须走事务并二次确认。

### 6.4 设置与 Key

- `key_store.dart` 只暴露 `read()` / `write()` / `clear()`，页面不直接碰 `flutter_secure_storage`。
- iOS 卸载重装 Keychain 可能保留；Android Keystore 随卸载清除。首启若发现 `baseUrl` 存在但 Key 缺失，提示「上次的 Key 已随系统清除，请重新填写」。
- 「测试连接」按钮发 `max_tokens = 8` 的请求，10 秒超时，结果只显示成功 / 失败码与延迟。

## 7. 契约工作流

改一个字段的完整流程，缺一步都不算完成：

1. 改 `packages/contracts/lib/src/*.dart` 的模型定义
2. `dart run build_runner build --delete-conflicting-outputs`
3. 引擎补迁移（若涉及落库字段）
4. 更新对应文档的字段表（技术方案 / API 参考 / 世界包 manifest）
5. 跑 `dart test` 与 `flutter test`
6. 在 PR 描述里写明「改了哪个字段、影响哪些页面、老数据怎么处理」

**禁止**：客户端手写字段、用 `dynamic` 绕过校验、先改代码后补文档。

## 8. 编码与提交规范

命名：

| 范围 | 规则 |
| --- | --- |
| 文件 | `snake_case.dart` |
| 类型与组件 | `PascalCase` |
| 函数与变量 | `camelCase` |
| 常量 | `lowerCamelCase`（Dart 惯例），公式常量集中在文件顶部 |
| 事件名 | 枚举 `TurnEvent` 子类，不拼字符串 |
| 数据库 | 表 `snake_case` 复数，字段 `snake_case` |

提交：

- 一条提交只做一件事；消息写「为什么」，不写「改了什么」。
- 提交前自检：`dart analyze && dart test`（packages），`flutter analyze && flutter test`（app）。
- 不提交 `build/`、`.dart_tool/`、签名文件、任何 Key。

## 10. 调试与排错

| 现象 | 先查 | 常见原因 | 动作 |
| --- | --- | --- | --- |
| 点开始没反应 | 设置页是否已配置 | `MODEL_NOT_CONFIGURED` 被 UI 吞掉 | 检查 `blocked` 态分支 |
| 回合卡在 `turnStart` | 网络与网关日志 | 供应商超时、代理、证书 | 看首字耗时；重试一次 |
| 正文有了但选项不出现 | 是否有 `narrationEnd` | 提取失败后提前抛错 | 查 `pendingRepair` 与 rejected ops |
| 数值不变化 | `statePatch` 内容 | 路径不在白名单被静默丢弃 | 查 `run_events(type='rejected')` |
| 同一回合推进两次 | `expectedTurn` | UI 未锁按钮 | 修状态机，不要靠队列兜底 |
| 叙事与状态矛盾 | 导演输出 vs accepted ops | 提取把「计划」当「已发生」 | 收紧提取 prompt 的时态铁律 |
| 首字很慢 | 上下文长度 / 供应商 | 模型选得太大、上下文没裁 | 降 `contextBudget`，换小模型 |
| 成本异常 | `usage_log.tokensIn` | 近期正文未截断 | 检查 `context.dart` 预算分配 |
| 库表不存在 / 启动崩 | 迁移 | 忘升 `schemaVersion` 或改列 | 补迁移，别删库了事 |
| 导入 `.world` 失败 | `manifest.json` | 校验和不符、`schemaVersion` 超范围 | 提示具体原因，不静默忽略 |
| Key 填了仍 401 | 供应商控制台 | 余额不足、模型名不存在、baseUrl 少了 `/v1` | 用「测试连接」定位 |
| iOS 回前台回合丢了 | 后台挂起 | 流在后台被系统断开 | 保留正文 + 重试，不硬撑后台任务 |

排错原则：先从 `run_events` 看这一回合到底发生了什么，再看 `usage_log` 的模型调用，最后才怀疑 prompt。**不要靠改 prompt 掩盖状态错误。**

## 13. 平台坑位

1. **iOS 后台挂起**：切后台后网络流会被系统断开。不要申请长后台任务硬撑；回前台提示重试，已落库的回合不受影响。
2. **Android 包体**：`sqlite3_flutter_libs` 会带多 ABI 的 so，用 `--split-per-abi` 或 App Bundle 控制体积。
3. **内存**：8k 上下文 + 流式缓冲 + 历史正文预读，低端机容易 OOM；列表用懒加载，正文只保留最近 3 回合在内存。
4. **中文字体**：全量思源宋体约 10 MB 以上，构建前跑子集脚本。
5. **Keychain 残留**：iOS 卸载重装 Key 可能仍在，需在首启做一致性检查。
6. **明文 HTTP**：Android 需 network security config 放行，仅用于本机网关；远程一律 https。
7. **文件访问**：`.world` 导入走系统文件选择器，不申请全盘存储权限。
8. **时区**：世界内时间用字符串，落库时间用 UTC 毫秒，展示时转本地时区。
