## 2. 技术选型

### 客户端

| 用途 | 选择 | 理由 |
| --- | --- | --- |
| 状态管理 | `flutter_riverpod` | 引擎对象可注入，测试可替换 |
| 路由 | `go_router` | 层级导航：世界库 → 世界 → 局 |
| 本地数据库 | `drift` + `sqlite3_flutter_libs` | 类型安全、迁移可测、纯 Dart 可在测试里跑 |
| 模型 | `freezed` + `json_serializable` | 契约单一来源 |
| Key 存储 | `flutter_secure_storage` | Keychain / Keystore |
| 文件与分享 | `file_picker`、`share_plus`、`path_provider`、`archive` | `.world` 导入导出 |
| 字体 | 思源宋体 / 霞鹜文楷（子集化） | 包体可控 |

### 引擎

| 项 | 选择 |
| --- | --- |
| 语言 | Dart（纯逻辑，不 import `flutter`） |
| HTTP | `dart:io` HttpClient 或 `http` + 自建流式解析 |
| ZIP | `archive` |
| 校验 | 手写校验器（白名单 + 范围 + 类型），不引运行时 schema 库 |
| 并发 | 进程内串行队列（`Completer` + 队列），压缩与导入用 `Isolate.run` |

### 模型

| 角色 | 档位 |
| --- | --- |
| 意图分类、导演、提取、助手 | 小模型 |
| 叙事 | 中等模型 |
| 卷末压缩 | 小模型 |

模型通过 `llm/gateway.dart` 统一调用，业务代码只传 `role`，不出现具体模型名。

## 3. 契约单一来源

`packages/contracts` 用 Dart 类 + 注解定义 `WorldBible`、`Identity`、`RunState`、`StateDelta`、`Choice`、`ScenePlan`、`WorldPackageManifest`：

```
contracts/lib/src/
  world.dart  identity.dart  run_state.dart  delta.dart  choice.dart  scene_plan.dart  manifest.dart
  contracts.dart   // 汇总导出
```

- 引擎与客户端都直接用这份模型，**不存在第二份字段定义**。
- JSON 序列化由 `json_serializable` 生成；改字段先改这里，再跑 `dart run build_runner build`。
- 任何字段变更必须同步更新[技术方案](./技术方案.md) 的字段表，否则视为未完成。

**禁止**：客户端另写一套字段名、用字符串拼状态路径、用 `dynamic` 绕过类型。

---

## 4. 代码约定

1. **每次改动保证可运行**：提交前至少 `dart analyze` + `dart test`（engine/contracts）与 `flutter analyze` + `flutter test`（app）。
2. **变更量最小**：不做顺手重构，不扩大改动范围。
3. **状态变更唯一入口**：所有 op 必须过 `validate.dart`，禁止绕过写库。
4. **UI 不解析正文**：数值只来自 `statePatch`。
5. **错误统一错误码**：见[API 参考](./API参考.md) §1，不抛裸字符串。
6. **日志结构化**：单行 JSON，含 `runId`、`turnNo`、`role`；不记 Key、不记完整 Key 所在 URL。
7. **prompt 与代码同仓**，改动必须跑黄金回合集。
8. **引擎不依赖 Flutter**：`packages/engine` 里出现 `import 'package:flutter/...'` 视为错误。

## 5. 测试策略

| 层 | 内容 | 工具 |
| --- | --- | --- |
| 规则单测 | 成功率边界（5/95）、分级阈值、clamp、突破公式 | `dart test` |
| 契约 | JSON 往返、缺字段、非法 op、路径白名单 | `dart test` |
| 数据层 | 迁移从 0 到最新、事务回滚、级联删除 | `dart test` + 内存 SQLite |
| 回放 | 固定 seed 重放旧存档，结果一致 | `dart test` |
| 模型网关 | 流式分帧、错误映射、重试策略（本地 mock server） | `dart test` |
| 黄金回合 | 8 条固定回合，录制模型响应做 fixture，离线比对 | `tool/golden` |
| 客户端 | 游玩页状态机、断流、选项渲染、设置页校验 | `flutter_test` |
| 导入导出 | `.world` 往返、校验和篡改被拒、超限被拒 | `dart test` |

黄金回合集是质量闸门：任何 prompt 或规则改动都要全绿才允许合并。**CI 不调用真实模型**，用录制的 fixture 保证可重复与零成本。完整用例、fixture 格式与发布准入见[测试与验收](./测试与验收.md)。

## 6. 本地开发

```
# 一次装齐（根目录）
flutter pub get

# 生成序列化代码
dart run build_runner build --delete-conflicting-outputs

# 引擎测试
cd packages/engine && dart test

# 跑 App
cd apps/mobile && flutter run

# 文档链接校验
dart run tool/check_links.dart
```

不需要 Node.js、npm、wrangler、Docker、任何本地服务。开发者只需 Flutter SDK + Xcode / Android Studio。

调试用真机或模拟器自带的 Key，**不要提交任何 Key**；`.gitignore` 覆盖 `**/.dart_tool/`、`build/`、`*.g.dart` 之外的生成物按团队约定、`.env` 与签名文件。

## 7. M0 任务拆解（按能力，不按时间）

| # | 任务 | 产出 |
| --- | --- | --- |
| 1 | 仓库与契约 | 三个包可安装、contracts 模型与序列化生成 |
| 2 | 本地库 | drift 建库、迁移、种子导入（苍梧） |
| 3 | 引擎骨架 | RunState 读写、StateDelta 应用、Validator |
| 4 | 规则与判定 | Resolver、分级、突破、终局触发 |
| 5 | 模型网关 | 三协议适配（Chat / Responses / Anthropic）、流式解析、重试、Key 读取、连接测试 |
| 6 | 回合编排 | 分类 → 判定 → 导演 → 叙事 → 提取 → 校验 → 落库 → 推送 |
| 7 | 客户端链路 | 世界库 → 设置 Key → 抽卡 → 序章 → 游玩 → 断线恢复 |
| 8 | 结算与回溯 | 人生档案、快照分叉 |
| 9 | 助手 | 随行模式问答 |
| 10 | 打磨 | 文风、节奏、黄金回合集、本地用量统计 |

**顺序不可乱**：5 与 6 之前客户端只能对着假数据调样式；7 之前必须有 6。

## 8. 验收标准（M0 DoD）

1. 用一个身份从序章完整玩完第一卷（30 回合左右），能正常结束或死亡
2. 死亡后能生成人生档案，并从关键节点开新世界线
3. 自由输入的三类结果都符合预期（行动 / 查询 / 越权）
4. 四类异常都有明确恢复路径：未配置 Key、断网、Key 失效（401）、模型超时
5. 黄金回合集全绿
6. 首字延迟 p95 < 2.5 s（受供应商影响，超时须可见可重试），单回合 token 与成本可在设置页查看
7. 任意一局重放（同 seed）结果一致
8. **飞行模式下**能打开所有已有存档、阅读历史正文、查看人生档案；仅推进回合时提示需要网络

## 9. 观测

每回合写一条本地 trace（`usage_log` + 结构化日志）：

```json
{
  "runId": "r_2b9", "turn": 18, "traceId": "t_8f2c",
  "models": [{ "role": "director", "name": "small-model", "tokensIn": 6100, "tokensOut": 420, "ms": 820 }],
  "degraded": false, "rejectedOps": 0, "roll": 37, "grade": "success"
}
```

设置页展示：p50 / p95 首字延迟、降级率、单回合平均 token、本月估算花费、提取失败率。

无服务端看板。诊断数据由用户主动「导出诊断包」后经系统分享发出。

## 10. 安全与隐私

- 模型 Key 只在 Keychain / Keystore；日志、导出包、崩溃信息一律不含 Key。
- 除模型请求外不发起任何网络调用；不做统计上报、不做远程配置。
- 导入的 TXT 原文只存 App 沙盒私有目录，永不进入 `.world` 导出包。
- 删除一局 = 级联删除快照与事件；「清空全部数据」需二次确认。
- 允许 `http://` 仅限本机网关（如 `127.0.0.1`），远程一律 `https`，设置页对 http 显示风险提示。

## 11. M1–M3 交付增量

引擎、契约、判定与压缩在 M0 就要按「世界可换」设计：`world_version` 是参数，不是常量。

| 里程碑 | 新增本地表 | 新增引擎能力 | 新增页面 | 进入门槛 |
| --- | --- | --- | --- | --- |
| M1 世界工坊 | `world_drafts` | 结构化访谈、八字段完整度、生成与一致性校验、冻结为本地版本 | 工坊、创作对话、草稿编辑器、试玩 | M0 判定「成立」，见[数据与验证指标](./数据与验证指标.md) §9 |
| M2 小说导入 | `import_jobs`（已建） | 本地 TXT 解析（Isolate 分块 parse → extract → merge）、实体审阅、`exportable = 0` | 导入向导、实体审阅 | M1 有草稿被实际游玩 |
| M3 分享闭环 | 无新表 | `.world` 导出/导入、`.run` 存档包导出/导入、校验和、版本兼容、世界库管理 | 世界库、导入导出、存档管理、人生卡片导出 | M1/M2 链路稳定 |

三处容易踩的坑：

1. **「发布」在单机形态下只有一个含义**：把草稿冻结成 `world_versions` 的一行，进入作者本地世界库。没有「公开可见性」，上线商店不构成分发渠道。
2. **导入原文只在私有目录**，任何打包、导出、分叉路径都不得读取它；`worlds.exportable = 0` 是硬约束，不是 UI 开关。
3. **契约先行**：新增字段先进 `packages/contracts`，引擎与 App 同时消费；不允许两边各写一份 JSON 结构。

每个里程碑的验收标准沿用各自文档（[世界创造与导入](./世界创造与导入.md) §7、[世界分享与本地世界库](./世界分享与UGC.md) §10），M0 的 DoD 不因后续里程碑而放宽。
