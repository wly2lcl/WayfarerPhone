# 世界人生模拟器 · 产品方案

> 版本：v0.3（单机离线）
> 最后更新：2026-10-23
> 配套文档：[技术方案与引擎契约](./技术方案.md)

---

## 0. 一句话定义

一个「世界可生成、可分享」的单机 AI 单人跑团。

玩家进入世界、被分配身份、过完一段人生；AI 担任幕后 GM 推进世界与 NPC；关键节点停下让玩家选择方向；随时可向一个不推进剧情的「穿越助手」提问。世界有三种来源（官方内置、对话共创、小说导入），做完可以把世界包导成文件给别人玩。App 完全离线运行，数据只在设备本地，模型由玩家自带 Key 直连。

---

## 1. 已定决策

| 决策项 | 结论 | 影响 |
| --- | --- | --- |
| 运行形态 | 纯单机 Flutter App | 无自建服务端、无账号、无社区、无公开分发 |
| 首发平台 | iOS + Android 手机，一套 Dart 业务层 | 双端审核；iPad / Mac 不承诺体验 |
| 数据存储 | 设备本地 SQLite（drift） | 备份靠导出，卸载即失 |
| 模型接入 | 用户自带 Key，直连三种协议之一（OpenAI Chat / OpenAI Responses / Anthropic） | 内置 DeepSeek 与 OpenAI 预设；Key 存 flutter_secure_storage；推理成本由用户承担 |
| 世界分享 | `.world` 文件经系统分享面板导出与导入 | 流通只发生在用户之间 |
| 存档迁移 | 独立 `.run` 存档包，与 `.world` 解耦 | 换设备可续玩；导入需本机已有对应世界版本 |
| 商业形态 | 一次性付费，无内购、无订阅 | 不承担推理成本，不做付费墙 |
| 一局形态 | 单世界、单身份、一段有始有终的人生 | 非无限流、非沙盒；存档以「局」为单位 |
| 裁决方式 | 规则 + AI 混合 | 代码管数值/生死/时间/判定，AI 管叙事与选项 |
| 视觉呈现 | 纯文字 + 排版，不做 AI 配图 | 零额外模型成本，包体与离线体验最优 |
| 关系系统 | 两轴亲和 + 信任，配六档关系标签 | 不做道侣/师徒/结拜系统 |
| 助手形态 | 仅随行模式，禁止剧透 | 问世界真相一律不答 |
| 记忆检索 | 实体标签 + FTS5 | M0–M3 不引向量，预留接口 |
| MVP 目标 | 先验证「玩」 | M0 只做内置世界，不做创作与文件分享 |
| 玩家动词 | 关键节点选项 + 自由输入 | 引擎需要意图解析层 |
| 单局长度 | 不设上限，可存档续玩，直到终局 | 上下文必须固定预算，不随回合增长 |
| 首发题材 | 修真 / 仙侠 | 境界即章节，寿元即时钟 |

## 2. 核心主张

产品成败不在 Flutter，而在「回合引擎」。AI 文字游戏通常死于两件事：AI 忘了自己写过什么（设定崩坏、死人复活）、AI 替玩家做决定（玩家沦为读者）。

因此确立五条不可妥协的原则：

1. **叙事是表现层，状态是唯一真相。** AI 只能「提议」变更，由代码裁决后落库。
2. **AI 只提议，代码裁决。** 数值、生死、时间流速、骰子判定由代码钉死，AI 无法直接改写。
3. **身份是处境，不是职业。** 好身份自带目标、枷锁与关系网，不需要玩家自己编设定。
4. **选择稀缺且有代价。** 不追求每回合都能选，追求每次选都真的改变走向。
5. **死亡是结局，不是失败。** 结算产生「人生档案」，可回溯重开，旧线保留为另一条世界线。

## 3. 一局的完整流程

```
世界书架 → 选择世界 → 身份抽取（3 张选 1 张）→ 序章（建立处境与目标）
        → 循环推进（日常 / 事件 / 关键节点选择）→ 终局 → 人生档案结算
        → 换身份重开（或回溯到某个关键节点，开启新世界线）
```

### 身份抽取，而非创建角色

玩家要的是「被丢进一个陌生处境」的张力，而不是捏一个最优解。抽三张选一张，稀有度和难度拉开差异，天然形成重开动机。

### 身份的设计标准

| 好 | 坏 |
| --- | --- |
| 你是镖局弃徒，师父的仇家正在找你，你还欠着三十两银子 | 你是剑客，攻击 80 |
| 你是外门杂役，灵根残缺，但藏着一枚来路不明的玉简 | 你是修士，悟性 9，根骨 7 |

一句话里必须同时含有：处境、目标、枷锁、关系。

## 4. 回合与节奏

### 4.1 两种推进

- **日常推进**：连续叙事，不打断。用于积累关系、铺伏笔、给出信息。
- **关键节点**：停下，给 3–4 个方向，每个都有隐藏代价。

节奏建议：**每 5–8 回合出现一个关键节点**。每回合都让玩家选会造成选择疲劳，体验会退化成视觉小说。

### 4.2 选项呈现

玩家只看到：文案 + 风险暗示（低 / 中 / 高）+ 少量条件提示。
不给数值，不写「成功率 65%」。判定在水面下进行，失败也要有体面的叙事结果。

### 4.3 自由输入的三种处理

玩家除了选选项，还可以自己写行动。引擎先分类，不直接丢给大模型：

| 类型 | 例子 | 处理 |
| --- | --- | --- |
| 可执行行动 | 「我去后山看看」 | 查可行性、扣消耗，交给导演推进 |
| 查询 | 「我身上还有什么」 | 直接查状态回答，不进入叙事 |
| 越权 / 不可能 | 「我直接飞升」 | 不做硬拒绝，做「世界内化拒绝」：你试着运转周天，丹田一阵刺痛，气血翻涌 |

第三种是体验分水岭。回一句「你不能这么做」会瞬间出戏；让世界自己给出代价，玩家反而觉得世界是活的。

### 4.4 数值面板只露 6 个

气血、神识、灵石、声望、关键关系、寿元余量。

再多玩家就开始算表格，AI 叙事也会被数值绑架。规则藏在水面下，但每次判定都真实生效。

## 5. 成长与终局（修真）

### 5.1 境界即章节

炼气 → 筑基 → 金丹 → 元婴 → 化神 ……

境界天然提供：章节骨架、成长反馈、阶段性高潮。一卷对应一个境界或人生阶段（20–40 回合），卷末做一次强制压缩与大事件。

### 5.2 寿元即硬时钟

每突破一次延长寿元，突破失败就是死。它把「可以一直玩」变成「每一步都有代价」，也为长局提供了天然的终局条件。

### 5.3 必须防「打怪升级」

如果长局内容全是刷秘境、夺宝、越阶杀敌，第 40–80 回合一定疲软。世界圣经中必须预埋**非战斗目标**：

- 宗门政治与派系站队
- 道侣、师门恩怨、因果
- 心魔与自我认知
- 一件必须用几卷时间才能查清的旧案

### 5.4 终局条件

寿元耗尽、飞升、身死道消、堕入心魔。终局之后进入结算，而不是提示「游戏结束」。

### 5.5 人生档案与回溯

结算给出一份「人生档案」：几个标签、几次关键选择、一句盖棺定论。

允许回到上一个关键节点重开，**旧线完整保留为「另一条世界线」**。同一个世界、同一个身份，一次游玩能产生多次消费，这是这个品类最强的复用点。

---

## 6. 穿越助手

与 GM 分离的第二个智能体，只读状态、不推进剧情。

| 模式 | 视角 | 能力 | 阶段 |
| --- | --- | --- | --- |
| 随行 | 角色视角，不剧透 | 回答「我现在知道什么」「这人可信吗」「我有哪些路可走」 | M0 |
| 上帝 | 世界视角，可剧透 | 回答世界规则、隐藏设定、势力真相 | M3 之后 |

M0 只做随行模式：成本低，且不会破坏悬念。助手的回答严格基于主角的「已知信息」，这也是信息差玩法的底层保障。

## 7. 世界从哪来

> 访谈字段、校验门槛与 TXT 导入管线见 [世界创造与导入](./世界创造与导入.md)。

三条路的实现难度差三个量级。三种来源最终都落在本地世界库，分享形态是 `.world` 文件。

### 7.1 官方内置

人工精修，是质量基准，也是新用户的第一印象。随包内置，开箱即玩。M0 只做这一个，做透。

### 7.2 对话共创

必须做成**结构化访谈**，不是自由聊天。AI 边聊边填满八个字段，聊完生成一张「世界卡片」让用户修改。

字段：时代、地理、势力、力量规则、禁忌、基调、NPC 池、事件种子。

纯聊天生成的世界，十有八九是空壳。

### 7.3 小说 TXT 导入

链路：分块 → 摘要 → 实体抽取（人物 / 地点 / 势力 / 关系 / 时间线）→ 生成世界圣经 → **强制人工过一遍编辑器**。分块与抽取在本地 Isolate 执行，断点可续。

直接把原文丢给 AI 跑，前三章还行，三十章必崩。

### 7.4 版权红线

**用户导入小说生成的世界，默认私有、不提供导出。**

原创世界可以导出为 `.world` 给他人；含原作用语、专有名词与原文段落的世界不导出。否则产品做大之日，就是侵权诉讼池成型之日。这条在数据模型上就要体现（导入来源的世界标记为私有，导出入口不出现）。

## 8. 分享

> 世界包格式与 fork 谱系见 [世界分享](./世界分享与UGC.md)；合规要求见 [合规与内容安全](./合规与内容安全.md)。

- **世界包**：`.world` 文件，内含 world.json（圣经）+ 身份池 + 事件种子 + 封面 + 版本号 + 许可证 + AI 标识 + 来源署名
- **传递方式**：导出走系统分享面板（AirDrop、微信、文件 App），导入走系统文件选择器；无服务器、无账号、无上传
- **版本冻结**：导出的包即一个快照，改内容即新版本；老存档继续读自己绑定的版本
- **可 fork**：导入的世界可复制为新草稿二创，包内保留来源与衍生关系
- **无平台审核**：只做本地结构校验；内容合规责任在使用者，App 不托管、不公开分发任何世界

## 9. 里程碑

| 阶段 | 范围 | 唯一目标 |
| --- | --- | --- |
| M0 | 修真世界 1 个、身份 8–10 个、1–2 卷、关键选择 + 自由输入、终局结算、随行助手、模型设置（协议 / 预设 / Key / 模型）、本地存档 | 验证「这个 AI GM 好不好玩」 |
| M1 | 对话式世界创造 + 世界编辑器（本地草稿） | 验证用户是否愿意造世界 |
| M2 | 小说 TXT 导入（本地 Isolate）+ 世界库、`.world` 导入导出 | 验证从已有作品生成世界的能力与版权边界 |
| M3 | 世界包分享闭环（导出 → 他人导入 → 试玩）、`.run` 存档包、用量统计 | 验证世界作为本地资产在玩家间流通的价值 |

**M0 如果不好玩，后面三个世界来源都是白搭。** 因此强烈建议只做 M0，做完再谈其他。

## 10. 风险清单

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 中期流失 | 第 40–80 回合玩家失去目标感 | 境界突破、卷末大事件、非战斗目标三条钩子 |
| 内容安全 | 自由输入 + AI 生成双重不可控 | 本地输入与输出双向过滤，越权行动由世界内化拒绝；不托管公开内容 |
| 同质化 | 修真题材竞品极多 | 差异必须落在「AI 真的记得你的选择」，而不是题材本身 |
| 模型供应商可用性 | 端点改版、下线、限流，用户 Key 失效 | 三协议适配（OpenAI Chat / Responses / Anthropic），协议、baseUrl 与模型均可切换；设置页提供「测试连接」与错误码直显 |
| 用户 Key 成本 | 长局 token 线性增长，费用由用户承担 | 固定 8k 上下文预算 + 卷末压缩 + 本地用量与成本估算，不设每日回合配额 |
| 双端审核 | iOS / Android 对 AI 生成内容、Key 输入与付费方式的规则差异 | 内置内容过滤与说明页，Key 输入不做外部支付引导，按双端规则分别提交 |
| 本地数据丢失 | 换机、卸载、系统清理导致存档与自建世界丢失 | 一键导出备份（存档 + 世界包），首次启动与设置页提示定期导出 |
| 导入版权 | 导入小说生成世界后导出传播 | 导入来源默认私有、不提供导出入口；包内写 AI 标识与来源 |
| 模型能力差异 | 不同模型文风与指令遵循差异大，叙事质量不稳 | 叙事模型与小模型分档配置、提示词分层、内置下限测试用例 |
