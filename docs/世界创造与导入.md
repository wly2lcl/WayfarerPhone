# 世界创造与小说导入

> 版本：v0.2（单机离线）
> 最后更新：2026-10-23
> 阶段：M1（对话共创）、M2（TXT 导入）
> 上游：[产品方案](./产品方案.md) ｜ 下游：[世界分享与本地世界库](./世界分享与UGC.md)
> 形态：纯单机 Flutter App；数据库为设备本地 SQLite（drift），迁移在启动时执行；模型由用户自带 Key 直连在线 API（OpenAI Chat / OpenAI Responses / Anthropic 三协议之一）。

三条世界来源最终都要产出同一样东西：一份可冻结的 `WorldBible`。区别只在「怎么填满它」。全部流程在本机完成，不涉及账号与服务端队列。

---

## 1. 统一的创建状态机

```
draft（访谈/选文件）→ generating（生成与校验）→ review（人工审阅）→ trial（试玩）
                                                              → frozen（冻结为本地版本）
```

无论哪条来源，都必须经过 `review`。**没有人工确认的世界不允许冻结**，这是内容质量与版权的双重闸门。

`frozen` 只表示「冻结成版本、进入本机的『我的世界』」，可导出 `.world`。导入来源的世界冻结后 `exportable = false`，App 内导出按钮不可用，只能自用。没有公开可见性，没有社区分发，见[世界分享与本地世界库](./世界分享与UGC.md) §2。

## 2. 数据结构

```ts
type WorldDraft = {
  id: string;
  source: 'manual' | 'dialogue' | 'import';
  status: 'draft' | 'generating' | 'review' | 'trial' | 'frozen';
  interview?: {
    step: FieldKey;
    answers: Partial<Record<FieldKey, unknown>>;
    completeness: number;          // 0–100，八字段加权
  };
  importJobId?: string;
  bibleDraft?: WorldBible;
  quality: {
    score: number;                  // 0–100，低于 70 不可冻结
    issues: { level: 'error' | 'warn'; field: string; message: string }[];
  };
  exportable: boolean;              // source === 'import' 时恒为 false
  updatedAt: number;
};
```

`WorldDraft` 与正式世界分离：草稿可以反复改，`world_versions` 一旦冻结即不可改。

```sql
-- 迁移由 drift 的 schemaVersion 在 App 启动时执行，只增不改

CREATE TABLE world_drafts (
  id TEXT PRIMARY KEY,
  source TEXT NOT NULL,              -- manual | dialogue | import
  status TEXT NOT NULL,              -- draft | generating | review | trial | frozen
  interview TEXT,                    -- InterviewState JSON
  bible_draft TEXT,                  -- WorldBible JSON
  quality TEXT,                      -- { score, issues } JSON
  import_job_id TEXT,
  exportable INTEGER NOT NULL DEFAULT 1,   -- 导入来源恒为 0
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE import_jobs (
  id TEXT PRIMARY KEY,
  draft_id TEXT NOT NULL REFERENCES world_drafts(id),
  status TEXT NOT NULL,              -- queued | parsing | extracting | merging | review | failed
  progress TEXT NOT NULL,            -- { stage, done, total } JSON
  stats TEXT, error TEXT,
  content_hash TEXT NOT NULL,        -- 断点续跑与重复导入去重
  source_path TEXT NOT NULL,         -- App 沙盒 files/imports/ 下的 TXT 原文，永不导出
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE INDEX idx_drafts_status ON world_drafts(status, updated_at);
CREATE INDEX idx_imports_draft ON import_jobs(draft_id);
```

## 3. 对话共创

### 3.1 为什么必须是结构化访谈

自由聊天生成的世界九成是空壳：没有势力关系、没有力量代价、没有可触发的事件。所以对话的目标不是「聊得开心」，而是**把八个字段填到达标**。

### 3.2 八个字段与达标线

| 字段 | 引导问题 | 达标线 |
| --- | --- | --- |
| 时代 | 这是什么样的年代？灵气的丰枯？ | 一句话时代 + 一个转折事件 |
| 地理 | 人主要活在哪几个地方？哪里危险？ | ≥ 3 个区域，各有用途 |
| 势力 | 谁在争什么？谁和谁不对付？ | ≥ 3 个势力，两两关系明确 |
| 力量规则 | 力量从哪来？代价是什么？上限在哪？ | ≥ 3 个层级 + 至少 1 条代价 |
| 禁忌 | 什么事绝对不能做？ | ≥ 3 条 |
| 基调 | 读起来应该是什么感觉？ | 3–5 个基调词 |
| NPC 池 | 这个世界里最关键的几个人是谁？ | ≥ 5 个，各有公开面与私密面 |
| 事件种子 | 有哪些迟早会爆发的事？ | ≥ 8 个，带触发条件 |

`completeness` 按字段加权计算，达不到 70 不允许进入 `generating`。

### 3.3 对话规则

- 一次只问一个字段，允许用户跳过（跳过则用安全默认值补齐并标记 `filledByAI: true`）
- 用户给出矛盾设定（如「灵气充沛」又说「末法时代」）时，当场指出并让用户选一个
- 不做开放式闲聊，每轮结尾必须推进到一个字段
- 访谈阶段不生成完整圣经，避免用户在长文里失去控制感

### 3.4 生成与校验

访谈达标后一次性生成 `bibleDraft`，随后跑一致性检查：

| 检查 | 规则 |
| --- | --- |
| 势力—地理绑定 | 每个势力至少有一个据点 |
| 力量有代价 | `powerSystem.costs` 非空 |
| 禁忌不自相矛盾 | 禁忌不得与主线目标直接冲突 |
| NPC 归属 | 每个 NPC 至少属于一个势力或明确为散人 |
| 种子可达 | `eventSeeds` 引用的区域、势力、NPC 必须存在 |
| 终局存在 | 至少 1 条 `EndingRule` 可被玩家实际触发 |

任何 `error` 级问题都会阻塞冻结；`warn` 只提示。

## 4. 小说 TXT 导入

### 4.1 管线

```
选文件 → 解码与分卷 → 分块 → 分块摘要 → 章节实体抽取 → 实体归并 → 关系图
       → 时间线 → 圣经生成 → 一致性消解 → 人工审阅 → 标记不可导出
```

每一步都可断点续跑（按内容 hash 与块序号写入 `import_jobs`），失败不清空已完成部分。App 被杀时任务停在最后完成的块，下次启动在导入向导中提示续跑。

### 4.2 参数

| 项 | 值 |
| --- | --- |
| 来源 | 本地文件选择器选取 `.txt` |
| 分块大小 | 3000 字 |
| 块间重叠 | 400 字 |
| 并发 | 顺序为主，最多 2 路（Isolate 内） |
| 单文件上限 | 20 MB |
| 编码 | UTF-8 / GBK 自动探测 |
| 实体归并 | 名称归一 + 别名表 + 人工确认 |
| 原文存放 | App 沙盒 `files/imports/`（私有，不可导出） |
| 执行位置 | Dart Isolate，本地后台 |

### 4.3 实体抽取的输出

```ts
type ImportEntity = {
  key: string;                      // 归一化名称
  type: 'character' | 'place' | 'faction' | 'item' | 'event';
  aliases: string[];
  firstSeen: { chapter: number; offset: number };
  frequency: number;
  attributes: Record<string, string>;
};
```

关系边（谁与谁、何种关系、从何时到何时）与时间线（大事件的先后）分别存储，用于生成 `npcPool`、`factions` 与 `eventSeeds`。

### 4.4 质量门槛

| 指标 | 门槛 |
| --- | --- |
| 主要人物覆盖率 | ≥ 80%（对比出现频次前 20 的角色） |
| 关系边数量 | ≥ 实体数 × 1.2 |
| 时间线冲突 | ≤ 5 处 |
| 一致性评分 | ≥ 70 |

未达标时**不允许进入试玩**，必须先由用户在编辑器里补。

### 4.5 进度与成本

导入在 Isolate 中后台执行，前端展示阶段与进度；进度写 `import_jobs`，不依赖任何远端任务队列。一本 30 万字的小说约 100 个分块、200 余次小模型调用。

费用由用户自己的 Key 承担，App 不抽成、不设每日配额，只把 token 用量写入 `usage_log` 做本地成本估算。

```ts
type ImportJob = {
  id: string;
  draftId: string;
  status: 'queued' | 'parsing' | 'extracting' | 'merging' | 'review' | 'failed';
  progress: { stage: string; done: number; total: number };
  stats: { chapters: number; chunks: number; entities: number; relations: number };
  error?: string;
};
```

### 4.6 版权硬约束

- `source === 'import'` 的世界，`exportable` 恒为 `false`，App 内导出按钮不可用，只能自用
- 导入原文只存 App 沙盒私有目录 `files/imports/`，不进入 `.world` 包
- 生成的圣经中保留「来源声明」字段；原创世界导出时可见
- 不提供「一键改写规避版权」的能力
- 无社区、无公开分发；版权责任由用户自行承担，导入向导中确认

详见[合规与内容安全](./合规与内容安全.md)。

## 5. 人工审阅（世界编辑器）

编辑器只允许改内容，不允许改运行时：

| 可改 | 不可改 |
| --- | --- |
| 全部圣经字段、身份池、种子 | `schemaVersion`、`world_version`、校验和 |
| 实体合并与拆分 | 已冻结版本的任何字段 |
| 基调与文风样例 | 终局条件的判定逻辑（只能选，不能写代码） |

审阅页需要提供：字段完整度、一致性问题列表、试玩入口、冻结按钮。导入来源的世界隐藏导出入口并说明原因，而不是点了再报错。

## 6. 本机引擎动作（M1 / M2）

以下均为进程内 Dart 调用，不是 HTTP 端点。单设备单写入者；同一 run 的回合由进程内串行队列保证串行，幂等由本地事务 + UI 状态机拦截重复提交实现。

| 调用 | 说明 |
| --- | --- |
| `WorldDraftService.create(source)` | 创建草稿（`source` 三选一） |
| `WorldDraftService.interview(draftId, text)` | 访谈一轮，流式回调推给 UI |
| `WorldDraftService.generate(draftId)` | 生成圣经并校验 |
| `WorldDraftService.get(draftId)` | 草稿、完整度、问题列表 |
| `WorldDraftService.save(draftId, patch)` | 编辑器保存 |
| `WorldDraftService.trial(draftId)` | 用草稿开一局试玩，不写正式存档 |
| `ImportService.pickAndStart()` | 选本地 TXT 并创建 `import_jobs` |
| `ImportService.progress(jobId)` | 进度与统计 |
| `WorldDraftService.freeze(draftId)` | 冻结为本地版本；导入来源可冻结但保持 `exportable=false` |
| `library.export(worldId)` | 导出 `.world`；导入来源按钮禁用（见[世界分享与本地世界库](./世界分享与UGC.md) §9） |

本地异常枚举（与[API 参考](./API参考.md) §1 同名同义）：

| code | 含义 |
| --- | --- |
| `DRAFT_INCOMPLETE` | 完整度不足，不可生成或冻结 |
| `QUALITY_GATE_FAILED` | 一致性检查未通过 |
| `IMPORT_TOO_LARGE` | 文件超出上限 |
| `IMPORT_INVALID` | 编码无法识别、文件损坏或结构解析失败 |
| `EXPORT_FORBIDDEN` | 该世界 `exportable = 0`，不可导出 |
| `WORLD_FROZEN` | 已冻结版本不可修改 |

## 7. 验收标准

1. 对话共创能在 10 轮内把八字段填到达标
2. 生成的世界能通过一致性检查并试玩一整卷
3. 30 万字小说导入可在一次任务内完成，且 App 被杀后可断点续跑
4. 导入来源的世界 `exportable` 恒为 false，导出入口不可用，任何本地操作都无法导出 `.world`
5. 编辑器的修改能正确反映到试玩，且不影响已冻结版本
6. 飞行模式下可完成审阅、试玩与本地世界管理，除模型请求外无网络依赖
