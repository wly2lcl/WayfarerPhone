# 规则与判定系统

> 版本：v0.2（单机离线）
> 最后更新：2026-10-23
> 上游：[Prompt 契约](./Prompt契约.md) ｜ 下游：[M0 内容包](./M0内容包-修真.md)

规则负责「能不能、成不成、代价多少」，AI 负责「怎么发生、写成什么样」。这一层全部是代码，可单测、可复现、可调参。

---

## 1. 三层规则

| 层 | 内容 | 谁执行 | 可变性 |
| --- | --- | --- | --- |
| 世界硬规则 | 力量体系、禁忌、境界上限 | 代码校验 + prompt 约束 | 随世界版本冻结 |
| 角色规则 | 属性、境界、状态、资源、寿元 | 代码 | 每回合变化 |
| 判定规则 | 成功率、掷骰、结果分级 | 代码 | 可全局调参 |

任何一层被 AI 违反，都在 Validator 阶段被拦下，不进入叙事。

---

## 2. 判定流程

```
输入意图
 → 1. 可行性检查（信息、物品、境界、地理、时间）
 → 2. 消耗结算（时间、神识、物品）
 → 3. 计算成功率
 → 4. 掷骰（引擎本地随机，seed 落库，可复现）
 → 5. 结果分级
 → 6. 生成 ResolverResult，交给导演
```

顺序固定。**随机数在设备本地生成并落库**，同一回合重放结果不变。

---

## 3. 成功率公式

```
成功率 = clamp(5, 95,
          50
        + 属性修正        // (attr - 50) / 5，范围 ±10
        + 境界差修正      // 每层差 12，clamp ±30
        + 环境修正        // -20 .. +20
        + 关系修正        // -10 .. +10（在场 NPC 的 affinity）
        + 状态修正        // 伤势、中毒、心魔，-30 .. 0
        - 难度偏移        // DC - 50
        )
```

难度偏移对照：

| DC | 含义 | 偏移 |
| --- | --- | --- |
| 30 | 容易，日常动作 | +20 |
| 50 | 普通，有不确定性 | 0 |
| 65 | 困难，需要本事 | -15 |
| 80 | 极难，九死一生 | -30 |

**上下限固定 5% / 95%**：永远不出现必成或必败，玩家才会觉得每次选择都有意义。

## 4. 掷骰与结果分级

`roll = 1d100`（本地引擎生成，写入 `run_events`）。

`margin = 成功率 - roll`

| 条件 | 分级 | 叙事含义 |
| --- | --- | --- |
| roll ≤ 5 | 大成功 | 目标达成，额外获得信息或资源 |
| margin ≥ 20 | 成功 | 目标干净达成 |
| 0 ≤ margin < 20 | 勉强成功 | 达成，但付出代价或留下后患 |
| -15 ≤ margin < 0 | 失败 | 未达成，暴露意图或位置 |
| roll ≥ 96 或 margin < -15 | 大失败 | 未达成，并触发新的麻烦 |

代码中的枚举：大成功 `critical_success`、成功 `success`、勉强成功 `narrow`、失败 `fail`、大失败 `critical_fail`，见[数据契约](./数据契约.md) §6。

**勉强成功要常见，大成功要稀有。** 这是文字冒险最重要的手感：大多数时候你赢了，但赢得不干净。

## 5. 冲突结算（不做回合制战斗）

逐回合战斗会把文字游戏的节奏拖垮，也会让成本翻倍。改成「一段冲突、最多三次判定」：

| 阶段 | 判定内容 |
| --- | --- |
| 试探 | 谁先看破对方路数，胜者获得优势点 |
| 交锋 | 主力对拼，胜者获得优势点 |
| 决胜 | 优势落后方必须冒险，判定失败即结束 |

先取得 2 个优势点者胜。三段全打完仍未分出，按优势点与剩余气血裁定。

结果交给叙事者写成一段连贯的动作场面，而不是逐招播报。

## 6. 突破与寿元

境界表（M0 内容，参数可调）：

| 境界 | 层级上限 | 寿元 | 突破基础难度 |
| --- | --- | --- | --- |
| 炼气 | 9 层 | 120 | 50 |
| 筑基 | 3 期 | 200 | 65 |
| 金丹 | 3 品 | 350 | 75 |
| 元婴 | 3 重 | 600 | 85 |

突破判定：

```
DC = 基础难度 + (目标层级 - 1) × 5 + 心魔 × 8
```

| 结果 | 后果 |
| --- | --- |
| 成功 | 境界提升，寿元上调至新境界，progress 归零 |
| 失败 | 气血 -30，寿元 -5，心魔 +1 |
| 大失败 | 走火入魔，触发终局条件 `ending_fall` |

突破是全局唯一能**上调寿元**的路径，因此必须由代码执行，AI 无权修改。

## 7. 行动可行性与消耗

### 可行性

依次检查：已知信息是否足够 → 物品是否具备 → 境界是否达到 → 地点是否可达 → 时间是否允许。任一项不满足，返回 `feasible: false` 与 `blockedReason`，导演需把拒绝写成「世界内化」的叙事，而不是系统提示。

### 消耗

| 行为 | 时间 | 资源 |
| --- | --- | --- |
| 日常行动 | 0.5–1 天 | 无 |
| 外出探索 | 1–3 天 | 少量灵石 |
| 闭关修炼 | 30 天–3 年 | 灵石、丹药 |
| 斗法 | 数刻 | 神识，可能重伤 |

### 防刷

同一目标重复行动，收益递减（第 n 次收益 × 0.6ⁿ），时间成本递增。避免玩家用「反复刷同一件事」绕过设计。

---

## 8. 成长

- `realm.progress` 范围 0–100
- 事件完成 +5–15，顿悟 +20–30，苦修按天折算
- 满 100 且资源满足，才允许尝试突破
- 境界内不再细分小等级，避免面板膨胀

---

## 9. 死亡与终局

| 触发 | 处理 |
| --- | --- |
| 气血 ≤ 0 | 濒死判定（DC 70，根骨/气运），失败即死 |
| 寿元 ≤ 0 | 自然死亡 |
| 心魔 ≥ 5 | 走火入魔，终局 |
| 满足 `EndingRule` | 飞升 / 身死道消 / 传承，进入结算 |

死亡后所有行动类 op 被 Validator 拒绝，只允许生成「人生档案」。**不得复活。**

## 10. 数值透明策略

| 展示 | 隐藏（仅定性描述） |
| --- | --- |
| 气血、神识、灵石、声望、关键关系、寿元 | 根骨、气运、心魔、成功率、DC |

隐藏项通过叙事传递：「你感觉根基发虚」「此人气息深不可测」「心底那点躁动又起来了」。

存储位置：根骨即 `character.stats.body`（面板展示名「体魄」）；气运与心魔存于 `flags.luck` 与 `flags.heartDemon`，缺省分别按 50 与 0 读取（见[数据契约](./数据契约.md) §4）。三者**不进面板、不进叙事数值**，但参与判定与终局条件。

## 12. 调参原则

1. 先看成功率分布，再看叙事。若某个身份长期成功率 < 30%，是难度设计错了，不是玩家菜。
2. 关键节点允许「必成但代价高」，日常行动不允许必成。
3. 任何数值调整必须能回放验证：用同一 seed 重放旧存档，结果应一致。
4. 参数集中在单一配置对象中，不散落在代码各处。
