# Prompt 契约

> 版本：v0.3（单机离线）
> 最后更新：2026-10-24
> 上游：[技术方案与引擎契约](./技术方案.md) ｜ 下游：[规则与判定系统](./规则与判定.md)

本文定义每个模型角色的职责、输入、输出与失败处理。**AI 只负责「怎么发生」，不负责「能不能发生」。**

---

## 1. 角色分工

| 角色 | 类型 | 职责 | 模型档位 | 是否流式 |
| --- | --- | --- | --- | --- |
| 意图分类器 Classifier | LLM（小） | 把自由输入分成四类，规范化意图 | 小 | 否 |
| 判定器 Resolver | **纯代码** | 可行性、消耗、掷骰、结果分级 | 无 | 否 |
| 导演 Director | LLM（小） | 决定本回合发生什么、释放什么信息、下一批选项意图 | 小 | 否（JSON） |
| 叙事 Narrator | LLM（中） | 把 scene plan 写成正文 | 中 | 是 |
| 提取 Extractor | LLM（小） | 从正文与计划产出 StateDelta、事实、伏笔、选项文案 | 小 | 否（JSON） |
| 助手 Companion | LLM（小/中） | 回答玩家提问，只读 `knowledge` | 小 | 是 |
| 访谈员 Interviewer（M1） | LLM（小） | 把用户对单个字段的回答整理成结构化 JSON；跳过时代填；检出矛盾 | 小（`interview`） | 否（JSON） |
| 构建者 Composer（M1） | LLM（中） | 由访谈回答一次性生成世界圣经骨架、NPC 池/事件种子/终局、身份池 | 中（`composer`，与叙事同档） | 否（JSON） |

一回合典型调用：**导演 + 叙事 + 提取 = 3 次**；自由输入多一次分类。查询类输入不进入导演与叙事。M1 世界工坊的调用不属于回合管线：访谈每轮 1 次小模型；生成一次性 3 次中模型（骨架 → 内容段 → 身份池）。

## 2. 回合时序

```
玩家输入
  │
  ├─ 选项 → 取出 choice.intent
  └─ 自由输入 → Classifier ──→ query/meta：直接查状态回答，结束
                          └─→ rejected：世界内化拒绝，结束
                          └─→ action：得到规范化 intent
  │
  ▼
Resolver（代码）：可行性 → 消耗 → 掷骰 → 结果分级
  │
  ▼
Director（LLM）：scene plan
  │
  ▼
Narrator（LLM）：正文流式输出 ──→ 进程内 Stream<TurnEvent> narration_delta
  │
  ▼
Extractor（LLM）：StateDelta + facts + threads + 选项文案
  │
  ▼
Validator（代码）：白名单、类型、范围、单调性、死亡后封锁
  │
  ▼
落库：snapshot + events ──→ 进程内 Stream<TurnEvent> state_patch / choices / turn_end
```

顺序不可换。**判定必须在叙事之前完成**，否则 AI 会先写「你赢了」，再被代码改成失败，玩家会看到自相矛盾的两次结果。

### 2.1 查询、meta 与越权分支

| 分类 | 走什么 | 是否推进回合 | 是否写状态 |
| --- | --- | --- | --- |
| `query`（问状态、物品、关系、已知信息） | Companion 通道，只读 `knowledge` + 当前状态 | 否 | 否 |
| `meta`（问玩法、规则、UI 操作） | 本地 FAQ 表直接回答，不调模型 | 否 | 否 |
| `rejected`（越权或违背硬规则） | 不掷骰，Director 只写「做不到」的世界内反馈 | 是（时间推进 0 天） | 否 |

这三类都不发 `choices` 与 `statePatch`；`query` / `meta` 只发 `TurnStart → Classification → narrationDelta* → narrationEnd → TurnEnd`，`rejected` 额外允许一次降级后的导演调用，失败则回固定文案。

## 3. 上下文装配顺序

所有 prompt 共用同一装配骨架，顺序固定，稳定前缀可逐字复用：

```
[1] 系统段       角色定义 + 全局铁律（稳定）
[2] 世界段       圣经摘要 + 禁忌 + 力量规则（稳定，同回合内复用）
[3] 身份段       身份卡 + 长期目标 + 枷锁（稳定）
[4] 记忆段       卷末压缩：事实清单 / 关系 / 开放伏笔（每卷变）
[5] 检索段       相关 NPC 私密面 / 地点 / 往事（每回合变）
[6] 近况段       最近 3 回合原文（每回合变）
[7] 任务段       本回合输入 + 输出约束（每回合变）
```

[1]–[3] 构成稳定的前缀，**同一回合内必须逐字一致**，便于供应商侧复用，占 8k 预算中的 1800。禁止把变化内容混进前缀。

## 4. 各角色契约

### 4.1 意图分类器 Classifier

**触发**：仅自由输入。

**输入**：玩家原文 + 当前状态摘要（地点、在场 NPC、已知信息）。

**输出**：

```json
{
  "kind": "action | query | meta | rejected",
  "intent": "规范化后的行动意图，一句话",
  "target": "npcId 或 placeId，可空",
  "confidence": 0.0
}
```

判定规则：

- `action`：在角色能力与信息范围内可尝试的行动
- `query`：询问状态、物品、关系、已知信息
- `meta`：询问玩法、规则、UI 操作
- `rejected`：越权或违背世界硬规则（「我直接飞升」），但**不硬拒绝**，交给导演做世界内化处理

**失败处理**：分类失败一律按 `action` 处理，交给 Resolver 判可行性。

**禁止**：不做数值判定，不生成叙事，不评价玩家。

---

### 4.2 判定器 Resolver

纯代码，**不调用模型**。规则细节见[规则与判定系统](./规则与判定.md)。

**输出**：

```json
{
  "feasible": true,
  "blockedReason": null,
  "cost": { "timeDays": 1.5, "spirit": 3, "items": [] },
  "check": { "stat": "body", "dc": 50, "roll": 37, "margin": 13, "grade": "success" }
}
```

`grade` ∈ `critical_success | success | narrow | fail | critical_fail`。

导演拿到的是**已裁决的事实**，只能据此编排，不能反转。

---

### 4.3 导演 Director

**职责**：决定这一回合「发生什么」。它是整个产品的节奏控制器。

**输入**：状态快照 + 判定结果 + 玩家意图 + 记忆四层。

**输出**：

```ts
type ScenePlan = {
  beat: 'daily' | 'event' | 'turning_point' | 'chapter_end';
  summary: string;                 // 一句话，给叙事者的指令，不给玩家看
  npcActions: { npcId: string; action: string; hidden: boolean }[];
  reveals: string[];               // 本回合释放给玩家的信息，必须来自 knowledge 新增
  mood: string;                    // 基调词：压抑 / 紧绷 / 松弛 / 惊悚
  nextChoices: {
    intent: string;
    risk: 'low' | 'medium' | 'high';
    requires?: { knowledge?: string[]; items?: string[]; realm?: string };
    hidden?: boolean;
  }[];
  advanceTimeDays?: number;
  chapterEnd?: { reason: string };
};
```

约束：

- `nextChoices` 固定 3–4 条，**必须互斥**，不能出现「都可以」的伪选项
- `reveals` 只能落在 `knowledge` 上，不得泄露 `npcPool` 的私密面
- `beat: 'turning_point'` 每 5–8 回合最多一次，由代码计数约束
- 不得在本回合直接宣告结局，结局只能由 Resolver 的终局条件触发

**失败处理**：重试 1 次；仍失败则降级为「保守日常」计划——不推进主线、不释放关键信息、只给 2 条安全选项，并记录 `degraded: true`。

---

### 4.4 叙事 Narrator

**职责**：把 scene plan 写成能读的正文。它是玩家 90% 的体验。

**输入**：scene plan + 判定结果 + 最近 3 回合原文 + 文风约束 + 已释放信息。

**输出**：纯文本，支持受限 Markdown（段落、斜体、对话、分隔线），**不支持表格、标题层级、代码块**。

篇幅：150–300 字。关键节点可到 500 字。章节收束可到 800 字。

硬性约束：

1. 第二人称「你」，不写玩家没有选择的行为
2. 不出现具体数值（伤害、成功率、修为点），只写体感
3. 不出现判定术语（「判定成功」「掷出 37」）
4. 已死亡的角色不得出场
5. 不得引入未在圣经或种子中登记的新势力、新地名、新境界
6. 不得替玩家做决定，不得写内心独白代替玩家立场

文风锚点（写进系统段）：冷峻、克制、少抒情；用动作与物象传递情绪；对话简短，不解释设定。

**失败处理**：非流式重试 1 次；仍失败则整回合回滚（不落库、不发 `state_patch`），前端提示重试。因为玩家已经看到了半截正文，不能带着错误内容继续。

---

### 4.5 提取 Extractor

**职责**：把「已经发生的事」翻译成结构化状态变更。它是唯一能写状态的模型。

**输入**：正文 + scene plan + 判定结果 + 变更前状态。

**输出**：

```json
{
  "ops": [{ "op": "inc", "path": "character.stats.vitality", "by": -8 }],
  "facts": ["你在药庐后墙发现了一枚带血的玉牌"],
  "openThreads": [{ "id": "t_jade", "desc": "带血玉牌的主人是谁", "dueChapter": 3 }],
  "closeThreads": ["t_master_death"],
  "choices": [{ "intent": "追问守夜人", "label": "拦住守夜人，问他昨夜去了哪" }]
}
```

约束：

- 只能使用白名单路径（见技术方案 §7）
- `facts` 必须是正文里真实发生过的，不得新增情节
- 选项文案由 Extractor 润色 `nextChoices` 的意图，不得改变意图本身
- 不得修改 `lifespan`、`chapter`、`ending_id`
- `ops` 数量上限 12 条，超出说明本回合推动过多，丢弃低优先级项

**失败处理**：不重试。正文照发、`state_patch` 为空、写入 `pendingRepair` 标记，下一回合的 Director 上下文里附带「上回合未结算：……」由代码补齐最小可推断变更。

---

### 4.6 助手 Companion

**职责**：回答玩家提问，不推进剧情、不改变状态。

**输入**：`knowledge` + 当前状态 + 关系表 + 最近 5 回合原文。**不注入 `npcPool` 私密面与事件种子。**

**输出**：纯文本，100–200 字，第一人称「我」的口吻，像随行者而非旁白。

拒答规则：

- 问「接下来会发生什么」→ 只给已知线索的推论，不做预言
- 问他人秘密 → 只回答「你目前不知道」，并说明判断依据
- 问世界真相 → 随行模式一律不答，提示「这些要靠你自己去看」

**失败处理**：返回固定文案「一时想不出该怎么答，先看看眼前吧」，不重试、不额外消耗调用。

---

### 4.7 访谈员 Interviewer（M1 世界工坊）

**职责**：把用户对一个字段的自由回答整理成结构化 JSON，同时做三件事——照原意收窄（不替用户发明设定）、识别「随便你/跳过」、检出与已有字段的矛盾。

**输入**：当前字段与引导问题 + 已有其他字段回答（只读，用于矛盾检查）+ 用户原文。

**输出**：

```json
{
  "skip": false,
  "contradiction": { "with": "era", "reason": "与灵气充沛冲突" },
  "data": { "...": "该字段的 schema，由字段决定" }
}
```

约束：

- 只整理用户说过的话；含糊就收窄成一句话，不扩写
- 名称一律保留为中文汉字，不得把用户口述的中文写成拼音或英文
- `skip = true` 时 `data` 留空对象，代填改由引擎发起的**代填调用**完成（同角色小模型，输入世界已有信息，产出恰好达标的默认值并标 `filledByAI: true`）
- 矛盾不阻塞：`data` 照常输出，由引擎把矛盾反问用户裁决

**失败处理**：解析失败视为空回答重新提问；重试 1 次后仍失败则提示用户换种说法。模板位于 `packages/engine/lib/src/world_draft/prompts.dart`。

---

### 4.8 构建者 Composer（M1 世界工坊）

**职责**：访谈达标后，一次性把八个字段变成可玩的世界。三次 JSON 调用：圣经骨架（meta/时代/地理/势力/力量/禁忌）→ 内容段（NPC 池 + 事件种子 + 终局规则）→ 身份池。

**输入**：访谈全部回答（`filledByAI` 字段显式标注「可调整但保持风格一致」）。

**约束**：

- 忠于用户回答：用户明确给出的名字、关系、代价不得替换
- 所有 id 英文蛇形命名加类型前缀（`fac_`、`reg_`、`npc_`…）；势力必须有据点；力量必须有代价；种子引用的区域/势力/NPC 必须存在
- 中文纯化：除 id（`era_`/`reg_`/`place_`/`fac_`…）外，所有输出（名称、摘要、提示、代价、禁忌）一律简体中文汉字；人名、地名、势力名不得使用拼音或英文单词（真机实测：小模型会把「云岫城」写成「Yunxiu City」、NPC 名写成拼音，已在各段系统/用户模板显式约束，见 §9.7）
- 冷峻克制，地名要像真的，不堆玄幻辞藻

**失败处理**：每段重试 1 次；仍失败则整次生成失败，草稿状态回滚，UI 给出可重试的错误。**模型输出容错按 §6 执行**——内容段偶发把对象写成字符串/数组时降级为空值，不炸整个解析（M1 真机实测根因）。

## 5. 全局铁律（写入每个角色的系统段）

1. 叙事是表现，状态是唯一真相。
2. 只能提议变更，不能直接改写状态。
3. 不替玩家做决定，不写玩家未选择的行为。
4. 不输出数值、成功率、判定术语。
5. 不引入未登记的新设定。
6. 角色死亡即永久，不复活。
7. 不符合世界硬规则与禁忌的内容一律不写。
8. 玩家已知信息 ≠ 世界真相，叙事只表达角色视角。

---

## 6. 输出解析与容错

| 情况 | 处理 |
| --- | --- |
| JSON 截断 | 提取最后一个完整对象，失败则重试 1 次 |
| 字段缺失 | 用 schema 默认值补齐 |
| 枚举越界 | 按最近合法值映射（如 `risk` 越界 → `medium`） |
| 路径非法 | 丢弃该 op，记录 `rejected_ops` |
| 正文过长 | 保留前 1200 字，尾部截断并记录 |
| 模型超时 | 30s 硬超时，走该角色的失败处理 |
| 对象字段写成字符串/数组 | 契约层容错降级：`rawMapOr` 返回空对象、数组里的非对象元素跳过（`asListOfMaps`），不让单字段畸形炸掉整份解析（M1 生成管线真机实测根因） |

### 6.1 模型能力差异兜底

不同供应商对 JSON 模式与流式的支持不一致，引擎按能力降级，契约不变：

- JSON：优先请求 `response_format: {"type": "json_object"}`；不支持则改用系统段前缀约束（「只输出一个 JSON 对象」）+ 截断修复 + 本地 schema 校验（等价 zod 的白名单式检查）。
- 校验失败仍按上表容错；重试 1 次后仍失败，走该角色的失败处理。
- 流式不可用：Narrator / Companion 退化为一次性返回，本地按段落分片渲染，观感仍是逐段出现，`TurnEvent` 顺序不变。
- 能力探测结果按「供应商 + 模型名」记在本地设置，失败一次即降级，避免每回合重复试探。

---

## 7. 前缀复用与成本

- [1]–[3] 段作为稳定前缀，按 run 绑定并逐字复用；是否命中供应商缓存由对方决定，不计入验收指标
- 导演与提取共用同一份世界段与状态段，减少重复计费
- 提取使用最小可用模型，它的任务只是结构化，不需要文采
- 每回合在本机 `usage_log` 记录：模型名、输入/输出 token、耗时、是否降级，用于后续调参与成本展示

---

## 8. 回归测试集

维护一组「黄金回合」（golden turns），每次改 prompt 必须全量跑通：

1. 正常选项推进
2. 自由输入可执行行动
3. 自由输入越权（应世界内化拒绝）
4. 查询类输入（不进叙事）
5. 死亡后行动（应封锁）
6. 关键节点生成（3–4 个互斥选项）
7. 卷末收束与压缩
8. 提取器产出非法路径（应被丢弃且其余生效）

判定标准：结构化输出可解析、状态校验零错误、叙事不出现数值与禁用词。

## 9. 系统提示词模板（v0）

以下为各角色系统段的最小骨架。`{}` 为装配槽位，取自 §3 的七段上下文；「稳定」槽位在同一 run 内逐字不变。模板作为代码常量存放在 `packages/engine/lib/prompts/`，改动需同步更新本节与黄金回合集。

### 9.1 公共铁律段（所有角色前置）

```
你是《{worldName}》这款文字人生模拟的幕后引擎。
世界的基调：{tone}。叙事人称：第二人称「你」。

铁律（任何情况下不得违反）：
1. 叙事是表现，状态是唯一真相；你只能提议变更，由代码裁决。
2. 不替玩家做决定，不写玩家未选择的行为，不写玩家的内心独白。
3. 不输出任何数值、成功率、判定术语、规则名词。
4. 不引入未在以下世界设定中登记的新势力、新地名、新境界、新物品。
5. 角色死亡即永久，不得复活，不得以回忆/幻象形式让其继续行动。
6. 违反世界硬规则与禁忌的内容一律不写。

世界硬规则：
{powerSystem.rules}

禁忌：
{taboos}
```

### 9.2 Classifier

```
你的唯一任务是判断玩家这句话属于哪一类，并规范化意图。不要解释，不要叙事。

当前处境：地点 {placeName}；在场 {presentNpcs}；已知信息 {knowledgeTop5}。

分类标准：
- action：在角色能力与已知信息范围内可以尝试的行动
- query：询问自身状态、物品、关系、已知信息
- meta：询问玩法、规则、界面操作
- rejected：越权或违背世界硬规则（如「我直接飞升」）

只输出一个 JSON 对象：{"kind":"...","intent":"一句话规范化意图","target":"npcId/placeId/null","confidence":0.0}
```

### 9.3 Director

```
你是这个世界的导演。判定结果已经由系统给出，你只能据此编排，不能反转成败。

本回合判定（已裁决，不可更改）：
{resolveResult}

玩家意图：{intent}

可释放信息池（只能从这里取，取多少由你决定）：
{pendingReveals}

你必须决定：这一回合发生什么、哪些信息被玩家看见、下一批选项是什么。
选项必须互斥且各有代价，3–4 条，不得出现「都可以」的伪选项。
未到期的伏笔只能轻轻触碰，不得一次揭穿。

只输出一个 JSON 对象，字段见 ScenePlan schema：
{scenePlanSchema}
```

### 9.4 Narrator

```
你负责把场景计划写成正文。你写的是玩家看到的一切。

本回合场景计划：
{scenePlan}

判定结果（只体现为体感，不得写出成败术语）：
{resolveResult}

最近三回合原文（延续语感，不重复内容）：
{recentTurns}

要求：150–300 字（关键节点可到 500 字，卷末可到 800 字）；第二人称；不出现数值与判定术语；
只写已发生的事与玩家可见的物象动作；对话简短，不解释设定；不出现表格、标题、代码块。
直接输出正文，不要任何前后缀。
```

### 9.5 Extractor

```
你的任务是把已经写好的正文翻译成状态变更。你不创作新情节。

正文：
{narration}

场景计划：
{scenePlan}

变更前状态（节选）：
{stateSlice}

允许写入的路径（白名单，其余一律不得出现）：
{writePathTable}

只输出一个 JSON 对象：
{"ops":[...],"facts":[...],"openThreads":[...],"closeThreads":[...],"choices":[{"intent":"...","label":"..."}]}

上限：ops ≤ 12 条；facts ≤ 6 条，每条 ≤ 80 字。
facts 必须是正文中真实发生过的事；choices 只能润色既有意图，不得改变意图。
```

### 9.6 Companion

```
你是随玩家同行的旅伴，不是旁白，也不是先知。你只知道玩家已知的信息。

你已知：{knowledge}；当前状态：{stateSummary}；最近五回合：{recentTurns}

回答要求：100–200 字，第一人称「我」，像同行者说话，不推进剧情、不改变状态。
- 问「接下来会怎样」：只给基于已知线索的推断，不做预言
- 问他人秘密：直接说「你目前不知道」，并说明判断依据
- 问世界真相：一律不答，回「这些得靠你自己去看」
```

### 9.7 装配与校验约定

- 槽位为空时整句删除，不输出「无」「null」字样
- 模板中的 JSON schema 由 `packages/contracts` 生成，不在模板里手写两份
- 每份模板改动后必须跑 §8 全部 8 条黄金回合；M1 访谈/构建模板改动还需跑 `dart test test/world_draft_test.dart`
- 模板文本纳入版本管理；每回合写一条 `type = system` 的 `run_events`，其 payload 记录 `{ roles: [...], promptVersion }`，便于回溯
- Composer 各段（骨架/内容/身份）与代填模板均含中文纯化约束行：除 id 外所有文案一律简体中文汉字，禁止拼音/英文名称
