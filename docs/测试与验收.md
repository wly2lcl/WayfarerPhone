## 1. 测试目标

| 目标 | 判定方式 |
| --- | --- |
| 数值可复现 | 同一 seed 重放旧档，事件流逐字节一致 |
| 状态可信 | 任何非法 op 都被 Validator 拦下，叙事与状态永不分叉 |
| 失败可恢复 | 模型超时 / 断网 / Key 失效 / 输出损坏都有明确出口，不卡死 |
| 内容不越界 | 不出现数值、判定术语、未登记设定、死者复生 |
| 单机自洽 | 除模型请求外，全流程在飞行模式下可用 |

测试不追求覆盖率数字，追求**关键路径上的确定性**。

## 3. 单元测试清单（L1 / L2）

### 3.1 规则与判定

| 用例 | 断言 |
| --- | --- |
| 成功率上下限 | 极端属性 + 极难 DC 仍落在 `[5, 95]` |
| 分级边界 | `roll = 5` → `critical_success`；`roll = 6` 且 `margin ≥ 20` → `success`；`margin = 0` → `narrow`；`margin = -1` → `fail`；`roll = 96` → `critical_fail` |
| 境界差修正 | 每层 ±12，叠加后 clamp 到 ±30 |
| 突破公式 | `DC = 基础难度 + (目标层级 - 1) × 5 + 心魔 × 8`，与[规则与判定](./规则与判定.md) §6 一致 |
| 突破结果 | 成功上调寿元、`progress` 归零；失败扣气血与寿元、心魔 +1；大失败触发 `ending_fall` |
| 消耗 | 闭关 30 天–3 年按天折算，灵石不足时 `feasible = false` |
| 防刷衰减 | 同一目标第 n 次收益乘 `0.6ⁿ`，n ≥ 5 时收益趋于 0 而非负数 |
| 终局表达式 | §13.3 原子全部可解析；非法表达式启动时报错而非静默忽略 |

### 3.2 校验器 Validator

| 用例 | 断言 |
| --- | --- |
| 白名单外路径 | op 被丢弃并记入 `rejected_ops`，其余 op 照常生效 |
| 类型错误 | `by` 传字符串 → 丢弃；不整体失败 |
| 数值越界 | `affinity` 超 `[-100, 100]` 时 clamp，不报错 |
| 引用完整性 | `npcId` 不存在 → 丢弃该 op |
| 单调性 | `lifespan` 只能由突破路径上调；AI op 写 `lifespan` 一律丢弃 |
| 死亡封锁 | `status = ended` 后所有行动类 op 被拒，仅允许档案生成 |
| 数量上限 | ops > 12 时丢弃低优先级项并记录 |
| 禁止写入 | `ending_id`、`chapter`、`meta.turnNo` 的写入全部被拒 |

### 3.3 契约（packages/contracts）

| 用例 | 断言 |
| --- | --- |
| JSON 往返 | 每个模型 `toJson → fromJson` 等值 |
| 缺字段 | 反序列化用默认值补齐，不抛异常 |
| 未知枚举 | 按最近合法值映射（如 `risk` → `medium`）并记日志 |
| 空槽位装配 | 上下文装配时空槽位整句删除，不出现 `null` / `无` |
| manifest | 字段与[数据契约](./数据契约.md) §10 完全一致；`checksum` 覆盖范围明确 |

## 5. 模型网关测试（L4）

用本地 mock server 模拟三种协议（OpenAI Chat / OpenAI Responses / Anthropic Messages），**不联网、不消耗真实 Key**。每种协议都要单独跑一遍下表；差异只在帧格式，断言的是同一份 `TurnEvent` 结果。

| 用例 | 构造 | 断言 |
| --- | --- | --- |
| 正常流式 | 按协议下发增量帧 + 结束信号（`[DONE]` / `response.completed` / `message_stop`） | 逐帧转 `narrationDelta`，末帧发 `narrationEnd` |
| 鉴权头 | 三种协议各发一次请求 | Chat/Responses 带 `Authorization: Bearer`；Anthropic 带 `x-api-key` + `anthropic-version` |
| system 段位置 | 三种协议各发一次请求 | Chat 在 `messages`，Responses 在 `instructions`，Anthropic 在顶层 `system`；模型收到的内容一致 |
| JSON 模式 | Chat / Responses 结构化角色 | 分别发 `response_format` 与 `text.format`；Anthropic 不发该字段，走前缀约束 |
| 半截断流 | 中途关闭连接 | 映射 `MODEL_NETWORK` / `MODEL_TIMEOUT`，整个回合回滚 |
| 非流式退化 | 返回单块 JSON | 按段落本地分片，事件顺序不变 |
| 401 / 403 | 错误体 | `MODEL_AUTH_FAILED`，不重试 |
| 429 | 带 `Retry-After` | 按头部退避，仅重试 1 次 |
| 首字超时 | 60 s 无首 token | `MODEL_TIMEOUT`，可重试 |
| JSON 损坏 | 截断对象 | 走 §6 容错；重试 1 次后按角色失败处理 |
| 能力降级 | 模型不支持 `response_format` | 记录「供应商 + 模型名」能力位，后续请求不再试探 |
| Key 边界 | 日志与 `usage_log` | 不出现 Key、不出现含 Key 的 URL |

## 6. 黄金回合集（L5）

固定 8 条回合，覆盖回合编排的全部分支。每次改 prompt、规则或提取 schema 必须全量通过。

| ID | 场景 | 关键断言 |
| --- | --- | --- |
| `g01` | 正常选项推进 | 3–4 条互斥选项；`statePatch` 至少 1 条 op；叙事 150–300 字 |
| `g02` | 自由输入可执行行动 | Classifier → `action`；判定在叙事前完成；无判定术语泄露 |
| `g03` | 自由输入越权 | Classifier → `rejected`；时间推进 0 天；不发 `choices` 与 `statePatch` |
| `g04` | 查询类输入 | 走 Companion，不产生 `check` 与 `delta` 事件；不推进 `turnNo` |
| `g05` | 死亡后行动 | `RUN_ENDED`；所有行动 op 被拒；仅可生成档案 |
| `g06` | 关键节点 | `nextChoices` 为 3–4 条且互斥；`beat = turning_point` 计数受 5–8 回合约束 |
| `g07` | 卷末收束与压缩 | 触发 `compact` 事件；压缩产物含事实 / 关系 / 伏笔 / 卷记四段 |
| `g08` | 提取器非法路径 | 非法 op 被丢弃，其余生效；`rejected_ops` 非空；叙事照发 |

### 6.1 fixture 格式

一条 fixture = 一次模型调用的**确定性替身**：

```json
{
  "id": "g01-director",
  "role": "director",
  "promptVersion": "v0",
  "requestHash": "sha256:…",
  "model": "mock-small",
  "response": "{\"beat\":\"daily\",…}",
  "recordedAt": 1761264000000
}
```

规则：

- 存放于 `packages/engine/test/golden/fixtures/<goldenId>/`，每个角色一个文件
- `requestHash` 由「装配后的完整 prompt + 角色」计算；prompt 改动导致 hash 变化时测试失败，提示重新录制
- `recordedAt` 仅用于追溯，不参与断言
- fixture 中不得出现真实 Key、真实用户内容；导入类用例使用虚拟文本

### 6.2 录制与回放

```
dart run tool/golden/record.dart g01   # 需本地配置 Key，仅开发者手动执行
dart run tool/golden/replay.dart       # 默认命令，纯离线
```

- 录制只用于生成新基线；**CI 只跑 replay**
- 重新录制必须在 PR 描述中写明原因（模型变更 / prompt 变更 / 规则变更）

### 6.3 断言维度

1. 事件序列：`TurnStart → … → TurnEnd` 顺序与类型集合一致
2. 状态：应用 `statePatch` 后与期望 `RunState` 全等（忽略 `updatedAt`）
3. 文本：无阿拉伯数字指标、无「成功率 / 判定 / DC / 掷骰」等术语
4. 选项：数量、互斥性、`label` 与 `intent` 分离
5. 成本：`usage_log` 记录的角色集合与调用次数一致

## 7. 回放与确定性

| 用例 | 断言 |
| --- | --- |
| 同 seed 重放 | 从同一快照重放 N 回合，`run_events` 逐条相等 |
| 跨版本冻结 | 老存档在世界版本升级后仍按原版本读取，不迁移 |
| 断点续跑 | 导入任务被杀后重启，从最后完成块继续，不重复计费 |

随机数一律由引擎本地生成并落库，**禁止使用 `Random()` 默认种子**。

| 用例 | 断言 |

## 9. 集成与端到端（M0）

| 场景 | 步骤 | 通过标准 |
| --- | --- | --- |
| 首次启动 | 安装 → 打开 → 世界库出现「苍梧」 | 5 s 内可交互，无网络请求 |
| 完整一卷 | 设置 Key → 抽卡 → 序章 → 玩到卷末 | 30 回合左右走完，卷末压缩触发 |
| 死亡结算 | 触发 `ending_death` | 生成人生档案，可开新世界线 |
| 回溯 | 从第 10 回合快照开新线 | 旧线保留，新线事件 seq 从 1 开始 |
| 助手问答 | 游玩中提问三次 | 有答、不推进回合、不写状态、不扣 `turnNo` |
| 存储告警 | 模拟剩余空间 < 阈值 | 提示清理或导出，不产生半写文件 |

### 9.1 文风盲评协议（WF-M0-10-02）

1. **取样**：从一局真机玩到卷末的完整局，用 UI 自动化滚动采集全部叙事段落（≥ 60 字）；抽取 5 段匿名样例，覆盖前期 / NPC 互动 / 中期危机 / 后期蛰伏 / 卷记压缩五种场景，去除回合序号与位置信息后以 A–E 标号。
2. **评分**：人工盲评者不知道样例来自哪段回合与哪个模型渠道，按 1–5 分评（5 = 苍梧文风完全达标：第二人称、冷峻克制、无解释性文字、暴力只写后果）。
3. **通过**：5 段均分 ≥ 4 且无任何一段 ≤ 2 分。
4. **复评**：提示词或叙事模型变更后需重新取样盲评。

> **执行记录（2026-10-25）**：样例 A–E 取自已落幕苍梧局（第 2 卷 · 第 34 回合）。用户委托 agent 代评（内容过长未逐段评）：A=4、B=4、C=3、D=5、E=4，均分 4.0、最低 3、无 ≤2 → **踩线通过**。代评非盲且为提示词作者，证据强度弱于本协议设计的人工盲评，仅作基线记录；提示词/模型变更后按第 4 条复评。

`.world` 相关用例：

| 用例 | 断言 |
| --- | --- |
| 往返一致 | 导出后重新导入，`bible` 与 `identities` 全等 |
| 校验和 | 改动任意一个字节 → `IMPORT_INVALID` |

## 11. CI 流水线与门禁

```yaml
analyze:      dart analyze (packages) + flutter analyze (apps)
test-unit:    dart test packages/contracts packages/engine
test-client:  flutter test apps/mobile
golden:       dart run tool/golden/replay.dart     # 零模型调用
links:        dart run tool/check_links.dart
```

门禁规则：

1. 任一任务失败即阻断合并，不设「先合后修」
2. 黄金回合必须在 `golden` 任务全绿；找不到 fixture 视为失败
3. `packages/engine` 中出现 `package:flutter` 导入直接失败
4. 文档内相对链接出现断链直接失败
5. 提交信息或 diff 中出现疑似 Key（正则匹配常见前缀）直接失败

## 12. 缺陷分级

| 级别 | 定义 | 示例 | 处理 |
| --- | --- | --- | --- |
| P0 | 数据损坏、状态分叉、无法开局 | 快照与事件不一致；回合写半截 | 立即修复，阻断发版 |
| P1 | 核心路径不可用 | 401 后卡死；黄金回合失败；卷末不压缩 | 当版修复，阻断发版 |
| P2 | 有替代路径的明显错误 | 选项不互斥；叙事出现数值；错误码错配 | 当版修复，可带条件发版 |
| P3 | 观感与文案问题 | 文案生硬、间距不一致 | 排期修复，不阻断 |

判定原则：**能污染存档的一律 P0**，与观感无关。
